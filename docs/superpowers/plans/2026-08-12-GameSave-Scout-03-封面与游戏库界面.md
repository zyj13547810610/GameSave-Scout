# GameSave Scout 封面与游戏库界面

> 文档性质：当前有效的模块设计与验收基准；适用版本：V0.1 及后续增强；最后更新：2026-08-28；状态：V0.1.x 游戏库与批量封面界面、V0.2.0 自定义分组、V0.2.1 批量存档工作台、V0.3.0 静态建议分组、V0.3.1 独立规则管理工作台、V0.3.2 存档位置存在性控件、V0.3.3 界面技术标识迁移、V0.3.4 顶部四入口/固定侧栏及 V0.3.5 引擎规则生态选择均已实现并通过当前范围人工验收；V0.3.6 封面自动优化、批量封面启动入口和浅层扫描层数已确认设计、尚未实现。

## 1. 模块目标

主界面以封面网格展示游戏库，并提供搜索、筛选、根目录管理和右侧游戏详情。每个游戏只设置一张封面，可从本地文件选择或直接粘贴剪贴板截图。

界面优先保持游戏库浏览上下文：打开详情时不切换整页，关闭后回到原卡片位置。

## 2. 主界面布局

应用壳层由以下区域组成：

- 全局顶栏：应用品牌、游戏库/批量存档/批量封面/规则管理四个一级入口、界面缩放和当前工作区操作。
- 游戏库左侧栏：只在游戏库工作区显示多个扫描根目录及扫描操作。
- 主工作区：游戏库、批量存档、批量封面或规则管理；三个工具工作区不保留空白目录栏，使用顶栏以下全部宽度。
- 详情层：选中游戏后从右侧显示的模态详情抽屉。

游戏网格使用响应式 CSS Grid。窗口或界面缩放改变时，浏览器根据可用宽度自动调整每行卡片数量；游戏数据和图片组件不会因此重新请求或重复创建整份游戏库。

### 2.1 应用视口壳层与滚动边界（V0.1.2 建立，V0.3.4 重构）

主页改为占满 `100dvh` 的桌面应用壳层，`html`、`body` 和应用外层不再承担页面级纵向滚动。壳层按固定单行全局顶栏、可选状态栏和 `minmax(0, 1fr)` 剩余工作区分配高度；所有参与内部滚动的 Grid/Flex 子项必须允许收缩并设置等效的 `min-height: 0`，不能由内容最小尺寸把壳层撑出窗口。引导式存档状态或全局错误出现时占用独立行，并自动缩短下面的工作区。

全局顶栏在所有一级工作区中保持可见且不换成第二行：

- 左侧品牌区固定为 `15.625rem`，与游戏库下方的目录栏等宽并始终显示完整名称和简介；中间按固定顺序显示“游戏库”“批量存档”“批量封面”“规则管理”，当前项使用 `aria-current="page"` 和紫色选中态。
- 四项都是直接切换主工作区的同级入口，不使用“工具中心”中转页、下拉菜单或左侧纵向工具列表。
- 四个入口按文字内容宽度组成靠左排列的紧凑标签组，不平均拉伸填满顶栏中段；当前项保持明确选中态，未选项使用低调深色背景。
- 右侧始终保留界面缩放；只在游戏库显示“添加游戏目录”等工作区相关操作，工具页自身操作继续放在各自固定标题区。
- `960 × 640`、110%/120% 等空间不足组合下保持完整品牌和 `15.625rem` 左栏，不使用 `GSS` 缩写，也不把目录栏压窄；可以隐藏“界面缩放”文字但保留原生档位选择，并压缩导航间距、内边距和非必要按钮文案。四个一级入口和当前选中态不能被隐藏到菜单中。
- 切换到任一工具页后，游戏目录栏隐藏，工作台占满顶栏下方宽度；返回游戏库后恢复搜索、筛选、目录和游戏内容滚动位置。进入工具前应退出批量选择并关闭详情或普通模态，避免不可见选择状态继续占用上下文。
- 从规则管理离开时继续执行未保存草稿确认；从批量封面离开时先关闭会话并清理临时候选，再完成工作区切换。导航不能绕过这两类离开保护。

内容区继续使用左右分栏。游戏库左栏在所有受支持窗口尺寸下固定为 `15.625rem`，不随窗口变窄而改变；两个栏位各自明确滚动边界：

- 左侧目录栏固定在内容区内。“游戏目录”标题及其下方的“启动时快速核验游戏”开关和 1～4 并发设置不滚动；目录卡片、扫描状态和操作按钮位于其下方的一条独立纵向滚动区域。
- 右侧游戏库把“我的游戏”、“游戏管理”双按钮组、批量选择操作栏、对应结果或错误以及搜索筛选工具栏放入固定控制区；移动建议、空状态和游戏网格放入唯一的游戏内容滚动区。
- 左右滚动互不影响；滚动到边界时通过 `overscroll-behavior` 阻止继续传递到外层。两个滚动区使用稳定的滚动条槽位，滚动条出现或消失不能引起卡片横向跳动。
- 搜索词、状态、引擎或 V0.2 分组筛选发生变化后，游戏内容区回到顶部；进入批量模式、打开详情或切换一级工作区不主动改变已保存的游戏库滚动位置。

打开详情或目录弹窗时，主页组件和两个内部滚动容器都不卸载。切换一级工作区时应保留游戏库视图状态；返回后恢复搜索、筛选、目录滚动位置和游戏内容滚动位置，并把焦点放回对应顶部“游戏库”入口或此前安全焦点。任何一级工作区都不读取或恢复 `window.scrollY`。

当前 pywebview 最小窗口为 `960 × 640`。主页在该尺寸下继续保留左右分栏，允许批量操作和筛选工具栏在各自区域换行，但顶部四个一级入口始终保持单行；不能为了固定区域而产生不可操作的横向溢出。右侧内容容器不超过 `44rem` 时，搜索框跨两列并与状态筛选组成第一行，引擎和分组筛选组成第二行；“管理分组”继续位于标题右侧的游戏管理组中，确保 120% 缩放下仍可见，又不会用五行单列挤占游戏滚动区。

### 2.2 统一深色滚动条（已实现）

所有 GameSave Scout 自有滚动区域使用同一套纯 CSS 深色滚动条，包括主页目录、游戏内容、批量封面队列、候选画廊、详情抽屉和设置浮层。不得引入 JavaScript 自绘滚动组件，也不得改变原生滚轮、触控板、拖动和键盘行为。

- 滚动条目标宽度约为 `10px`，轨道透明或使用接近所在面板的 `#17151e`。
- 滑块使用圆角灰紫色：默认约 `#4d4856`，悬停约 `#686173`，拖动约 `#81778f`；滑块与轨道之间保留细小间隔。
- WebView2 下隐藏不符合深色主题的白色上下箭头按钮。只有内容溢出时才显示滚动条。
- 同时提供标准滚动条属性和 WebKit 兼容样式；不支持主题能力的环境退回系统滚动条，不影响可用性。

## 3. 游戏卡片

每张卡片显示：

- 2:3 封面缩略图；没有封面时显示标题首字符占位图。
- 游戏标题。
- 可选版本号，以弱于标题的次要文字或标签显示；为空时不占位。
- 安装状态。
- 已识别或手动设置的引擎标签。

卡片标题允许省略显示，但保留完整文本提示。点击卡片打开详情，键盘焦点进入抽屉；关闭后焦点返回原卡片。

主界面支持：

- 按标题或版本号即时搜索。
- 按 `installed`、`missing`、`save_only` 状态筛选。
- 按当前采用的引擎筛选。
- V0.2 按“全部分组”“未分组”或一个具体自定义分组筛选。
- 无游戏、无搜索结果、连接失败和扫描错误等独立状态。

### 3.1 主页批量管理（V0.1 建立，V0.2 扩展分组，V0.3.4 补齐仅存档删除）

“我的游戏”标题右侧提供固定“游戏管理”视觉组，内部并列“批量选择”和“管理分组”两个独立按钮。视觉分组不改变交互类型：“批量选择”切换页面内批量状态，“管理分组”打开模态窗口，二者不得合并为下拉菜单。普通状态显示“批量选择”，进入后在原位置显示“退出批量选择”，不因进入批量模式而消失。进入批量模式后：

- `installed`、`missing` 和 `save_only` 卡片左上角均显示复选框；点击卡片任意区域切换选择，不打开详情。
- 选中卡片使用明显边框和半透明高亮，同时保留键盘焦点样式。
- 主页批量删除仍只接受 `installed` 和 `missing`；选择中包含 `save_only` 时禁用删除，提示用户打开详情删除卡片或前往批量存档撤销创建，但分组操作保持可用。
- 搜索、状态和引擎筛选继续可用；切换筛选不会清除此前选中的隐藏项目。
- “全选当前结果”只把当前筛选后可见且允许批量处理的卡片加入选择，不移除其他已选项目。

批量模式下始终显示操作栏，内容包括：已选择总数、其中已安装/失效/仅存档数量、全选当前结果、清空选择、调整分组和删除所选。退出动作只保留在标题栏原位置的模式开关，避免操作栏出现第二个退出入口；退出批量模式会清空选择。没有选中项目时操作按钮不可用；选择包含 `save_only` 时只禁用删除并解释原因，调整分组仍可用。

最终确认框分别说明两类结果：已安装项目会从库中移除并加入各自根目录精确排除项；失效项目会删除数据库记录。确认框同时明确不会删除游戏文件、外部存档或用户原始封面。

成功后前端清空选择、退出批量模式、只刷新一次游戏库，并显示已安装处理数、失效处理数、更新根目录数及封面清理警告摘要。整批验证失败或记录状态变化时不显示部分成功，刷新游戏库后要求用户重新选择。

“我的游戏”标题及其右侧“游戏管理”按钮组作为一个独立标题栏，与下方搜索和筛选工具栏保留稳定间距。组内顺序固定为“批量选择”在左、“管理分组”在右；按钮换行时仍由标题栏统一提供间距，不能依赖标题文字自身的下外边距撑开布局。批量封面已迁入全局一级导航，不再占用该标题栏。

V0.2 在同一批量管理模式中增加“调整分组”，不新增第二套批量选择状态。分组操作允许选择 `installed`、`missing` 和 `save_only`；既有删除操作仍只接受 `installed` 与 `missing`。如果当前选择包含 `save_only`，删除按钮禁用并说明原因，不能把新增分组授权扩展成删除授权。批量归组浮层要求用户选择一个分组及“加入”或“移出”，确认后一次事务处理最多 500 个游戏，并显示实际新增、移除和未变化数量；成功后保留当前选择，方便继续整理。

仅存档卡片的详情底部提供独立“删除仅存档卡片”危险操作。确认文案必须说明该操作会删除整张卡片、恢复所有来源候选，但不会删除实际存档；成功后关闭详情并刷新游戏库。主页批量模式不复用这个入口，避免把面向游戏本体的批量移除语义与存档审核回退混在一起。

### 3.2 V0.2 自定义分组与筛选（已实现）

主页搜索筛选工具栏增加单选分组下拉框：

- “全部分组”不限制归属。
- “未分组”只显示没有任何分组关系的游戏。
- 具体分组显示属于该分组的游戏。
- 分组条件与搜索、状态和引擎条件取交集。
- 分组变化后游戏内容区回到顶部；当前筛选分组被删除时自动恢复“全部分组”。
- 选择状态只属于当前运行会话，第一版不写入 `data/config.json`。

“管理分组”入口位于“我的游戏”标题右侧的“游戏管理”按钮组中，打开当前窗口内的模态浮层，不创建新页面或原生窗口。所有普通模态遮罩统一位于固定工具栏、批量卡片选择框和详情抽屉之上，底层控件不能穿透或覆盖浮层。浮层支持新建、重命名和删除，并显示每组游戏数量。名称编辑失败或冲突时保留输入；删除前二次确认并明确“只删除分组关系，不会删除游戏”。最多允许 200 个分组，列表按创建顺序稳定显示。

游戏卡片第一版不铺设分组标签，以保持当前网格密度；用户通过筛选器和详情抽屉查看归属。第一版也不提供嵌套、颜色、图标、自动规则、多分组交并组合或拖放排序。

### 3.3 V0.2.1 批量存档一级页面（已实现）

“批量存档”位于窗口顶部全局一级导航，与“游戏库”“批量封面”“规则管理”同级。游戏目录栏只属于游戏库；切换到批量存档后目录栏隐藏，独立工作台使用顶栏下方全部宽度。顶部“游戏库”始终可见，负责返回游戏库，不新增工作台内部的重复返回入口。

工作台从上到下使用固定标题操作区、运行时进度、固定搜索筛选栏、唯一候选滚动区和按需出现的底部批量操作栏。扫描设置采用锚定浮层，不在页面内直接展开挤压结果；点击浮层内部保持打开，点击外部关闭且保留本次临时范围。筛选包括全部、待处理、已安装、本体失效、未关联、已记录、已忽略和不可用；状态、可信度与来源选择后立即应用，关键词停止输入 300ms 后应用，按 Enter 可立即应用。

宽窗口可以使用候选列表加右侧证据详情；窄窗口改为单列卡片内展开。80%～120% 五档缩放都必须可操作，960×640 且 120% 时仍要保留结果滚动区域；底部操作栏允许换行但不能覆盖候选。候选的扫描、识别、审核和安全边界由模块 06 定义。

### 3.4 V0.3.1 规则管理一级页面（已实现并通过人工验收）

“规则管理”位于窗口顶部全局一级导航，与“游戏库”“批量存档”“批量封面”同级。规则管理使用独立全页面工作台，不塞入详情抽屉，也不新建 Windows 窗口；进入后游戏目录栏隐藏。工作台内部固定“引擎规则”“存档规则”“Ludusavi”三个标签；标签下方固定搜索、来源筛选、状态筛选、新建和导入工具栏。

正常宽度下，剩余区域分为左侧规则列表和右侧详情/编辑器：

- 左侧标题与计数固定，只有规则列表独立滚动；列表条目同时显示名称、稳定 ID 摘要、内置/用户来源、已验证/实验和启停状态。
- 右侧标题与“规则详情 / YAML 预览”切换固定，中间表单或详情独立滚动，底部测试、保存、复制、启停等主要操作固定。
- 内置规则详情只读，操作限于本地启停、复制为用户规则和只读测试；用户规则使用同一区域编辑，离开未保存草稿前必须确认。
- 表单中的启用状态使用“已启用 / 已停用”明确下拉框，不使用语义不明显的无标题勾选框；“转到本地测试”必须平滑滚动并把键盘焦点移到测试区，不能触发测试或停留在原位置。
- V0.3.5 的引擎规则基本信息增加“适用生态”下拉框，固定选项为“通用 / 主流游戏”和“视觉小说 / 同人游戏”。新建规则初始显示“未分类（请选择）”且在选择前不能保存；旧用户规则缺少字段时显示“未分类”，仍可编辑和保存，不自动补写分类。
- “在本地游戏上测试”先通过本地输入框按标题即时筛选已安装游戏，再从原生下拉框选择目标；筛选不请求后端，当前选择被排除时立即清空并禁止执行测试，无匹配项时显示明确空状态。
- 新建和编辑不额外套大型弹窗；删除、覆盖导入等危险操作才使用确认弹窗。普通弹窗位于所有固定区和原生选择框之上，点击遮罩可关闭非危险弹窗并保留草稿。

110%/120% 或有效宽度不足时不把两列强行压窄：先全宽显示规则列表，点击后进入全宽详情/编辑器并提供“返回规则列表”。此时顶部标签和底部主要操作仍固定，中间只保留一个内容滚动区。五档缩放、`960 × 640` 最小窗口、默认和宽屏窗口都必须验收；滚动条沿用现有深色样式，页面外层不得出现第二条白色滚动条。

游戏详情存档区增加“为此游戏创建专属存档规则”入口，点击后切换到规则管理的存档规则标签并打开已预填草稿；返回游戏库时恢复原筛选、滚动位置和详情上下文。游戏详情只显示 Ludusavi 简要来源状态和跳转规则管理入口，不重复完整更新设置。

## 4. 详情抽屉

详情抽屉固定在窗口右侧，拥有自己的纵向滚动区域。当前实现宽度为：

```css
width: clamp(32rem, 40vw, 48rem);
max-width: 92vw;
```

正常窗口下以主窗口可视宽度的 40% 为目标；较窄窗口受 32rem 最小可用宽度约束，特别窄时再由 `max-width: 92vw` 限制；超宽窗口不超过 48rem。界面缩放仍通过现有 `rem` 体系影响最小和最大宽度。

### 4.1 内容顺序与视觉层级

详情内容固定按以下顺序排列：

1. 顶部概览。
2. 封面操作。
3. 游戏设置。
4. 存档位置。
5. 自定义分组。
6. 游戏引擎。
7. 游戏记录。

游戏设置和存档位置是主要工作区，使用正常强调的卡片；游戏引擎是低频诊断区；游戏记录是最底部的危险操作区。各功能区独立展开，不使用“展开一个便自动关闭另一个”的手风琴限制。

每次打开详情恢复固定默认状态，不跨游戏、不跨关闭操作记忆折叠状态：

- 游戏设置、存档位置默认展开。
- 自定义分组、游戏引擎、游戏记录默认折叠。
- 高级启动设置、存档位置高级信息、存档规则设置默认折叠。

### 4.2 顶部概览与封面

顶部采用居中大封面方案：

- 详情始终请求规范化原图，使用 `object-fit: contain` 完整显示，不进行 2:3 裁剪。
- 封面框居中，以 `46vh` 为目标高度并以 `22.5rem` 为最大高度：常规窗口保留现有大封面上限，低高度窗口自动缩短；无封面时继续显示稳定占位图。两个约束使用独立 CSS 属性表达，不依赖组合尺寸函数。
- 封面框必须形成独立裁剪边界。原图按自身比例缩放，最大宽度和最大高度都不能超过封面框；任何横图、竖图或异常长宽比图片都只能占据标题上方区域，不能覆盖标题、快捷按钮或后续封面操作区。
- 封面下依次显示完整标题、可选版本标签、安装状态和当前采用的引擎标签；版本号不拼入标题字段。
- “启动游戏”作为主操作，“打开安装目录”作为次操作，均放在顶部快捷区。
- 紧接概览的是封面操作栏，提供选择/替换本地图片、粘贴截图和移除封面。

顶部快捷操作不取代后续设置内容。安装路径和主程序仍在游戏设置中完整显示。

### 4.3 游戏设置

游戏设置默认展开，包含：

- 可编辑标题、可空版本号及统一的“保存游戏信息”操作；两个字段由同一个后端事务原子保存。
- 完整安装路径以可点击路径控件显示，点击后进入该目录。
- 当前主程序相对路径及“选择/重新选择主程序”。
- “重新检测主程序和引擎”操作；它只启动当前游戏的局部后台任务，忽略缓存重新分析，不触发整根目录扫描。
- 默认折叠的高级启动设置：工作目录、参数和环境变量。

顶部已经提供启动和打开目录快捷操作后，游戏设置不再重复放置另一个独立“打开文件夹”按钮；安装路径控件本身仍可点击打开。

### 4.4 存档位置

存档位置默认展开：

- 标题行放置“手动添加”和“全部验证”。
- 已确认位置按卡片显示；路径本身可点击打开。
- 来源、可信度、确认状态和是否存在使用紧凑标签表达。
- 路径模板与识别依据放在每张位置卡片的“高级信息”内。
- “查找存档位置”只在用户主动点击后执行并显示结果，不因打开详情自动扫描。
- 查找完成后先显示实际存在的“已找到”，规则可推导但当前不存在的候选放入默认折叠的“可能路径 / 未发现”；卡片继续显示精确、可能或实验标签。
- 同一路径的自定义、内置、Ludusavi 与引擎证据合并显示；预测项和注册表项不默认勾选，接受失败保留当前结果与选择。
- Ludusavi 状态、清单更新和自定义目录位于默认折叠的“存档规则设置”中。

### 4.5 自定义分组（V0.2.0 已实现）

存档位置之后增加默认折叠的“自定义分组”区，以多选项展示全部分组，避免分组数量较多时每次打开详情都形成过长列表：

- 用户可同时选择多个分组，点击“保存分组”后一次原子替换当前游戏的全部关系。
- 没有任何分组时显示明确空状态和“管理分组”入口。
- 保存失败时保留尚未提交的选择与错误，允许原地重试。
- 管理浮层中新建、重命名或删除分组后刷新可选项；若当前筛选分组被删除，主页恢复“全部分组”。
- 区块适用于 `installed`、`missing` 和 `save_only` 详情。

### 4.6 游戏引擎

现有自动识别结果与手动引擎设置合并成一个默认折叠的“游戏引擎”卡片：

- 折叠标题显示当前引擎、自动/手动状态和可信度。
- 未知或歧义结果在折叠标题显示黄色状态，但不自动展开。
- 展开后显示当前采用值、最近自动检测结果和手动引擎选择。
- 识别证据作为内部二级折叠项。

### 4.7 游戏记录

游戏记录位于最底部并默认折叠，使用暗红边框和弱红色背景；只有最终危险按钮使用明显红色：

- 已安装游戏提供“从库中移除并忽略”。
- 本体失效游戏提供“删除失效记录”。
- 说明文本必须明确不会删除游戏本体或外部存档。
- 执行前继续要求二次确认。

### 4.8 关闭方式

抽屉只保留右上角一个关闭按钮，并支持：

- 点击左侧半透明遮罩关闭。
- 按 `Esc` 关闭。
- 关闭后恢复打开详情的卡片焦点。

抽屉内普通空白区域不关闭，避免编辑表单时误操作。

### 4.9 滚动行为

- 抽屉打开时锁定主页目录和游戏内容两个内部滚动容器，不依赖 `body` 滚动锁或右侧宽度补偿。
- 遮罩拦截滚轮，不让底层目录或游戏内容随详情滚动；关闭后两个滚动位置保持不变。
- 抽屉内部独立滚动，并使用 `overscroll-behavior` 阻止滚动链传回主页。
- 抽屉滚动条位于抽屉内部并使用统一深色主题，不与页面级滚动条并排显示。

### 4.10 网格策略

打开抽屉时，主界面网格不为抽屉重新缩窄和重排。抽屉以覆盖层形式显示，左侧加 22% 黑色半透明遮罩。

选择覆盖方案的原因：

- 用户打开详情时主要关注当前游戏，不需要同时操作网格。
- 不会因网格列数变化造成卡片大幅移动。
- 大型游戏库不发生额外布局抖动。
- 点击遮罩即可清楚返回游戏库。

### 4.11 加载、错误与数据行为

- 重排只改变展示结构，不新增自动扫描、网络访问或游戏目录读取。
- 折叠和展开不销毁区块数据，也不重复请求整份游戏详情。
- 封面、标题与版本号、启动、存档、引擎和记录操作继续在各自区块附近显示忙碌状态与错误；游戏信息任一字段保存失败时保留两个输入值并且不产生部分更新，顶部快捷操作失败时在快捷区显示可读错误。
- 单游戏重新检测使用独立任务轮询并支持取消；成功后只用后端返回的最新游戏替换当前详情，失败或取消保留原结果。轮询期间用户尚未保存的标题和版本号输入不会被任务刷新覆盖，组件卸载时清理轮询计时器。
- 关闭详情会清除临时错误和折叠状态；不会清除已经成功保存的游戏数据。
- 组件测试覆盖内容顺序、默认折叠状态、顶部快捷操作、原图 URL、路径打开以及安装/失效两类危险操作。
- 新布局人工响应式验收覆盖 80%、90%、100%、110%、120% 全部五档界面缩放，以及最小窗口 `960 × 640`、默认窗口 `1180 × 760` 和宽屏窗口。

## 5. 键盘与可访问性

- 抽屉使用 `role="dialog"` 和 `aria-modal="true"`。
- 打开后把焦点移入抽屉。
- `Tab` 和 `Shift+Tab` 在抽屉可聚焦元素间循环。
- `Esc` 与关闭按钮行为一致。
- 图标按钮提供明确的 `aria-label`。
- 加载和操作结果使用 `aria-live`，错误使用 `role="alert"`。
- 80% 缩放和窄窗口下，顶栏、工具栏和操作按钮允许换行，不能横向溢出。
- 每个内部滚动区域都可通过键盘进入和滚动，浮层打开后 `Esc` 优先关闭最内层浮层。

## 6. 界面缩放

当前提供五档整体缩放：

- 80%
- 90%
- 100%
- 110%
- 120%

缩放通过根元素 CSS 变量 `--ui-scale` 调整基础字号，使用 `rem` 的布局和控件随之变化。当前选择值由 Python 原子写入程序旁的 `data/config.json`，不受本地资源服务随机端口影响。

应用启动从 `bootstrap()` 取得 `uiScale`；旧版配置自动迁移，缺失或非法值回退到 100% 并尝试写回规范值。前端不再读取或写入 `localStorage`，旧页面来源中的残留值不会覆盖便携配置。

用户切换档位时先立即应用，再调用 Python 串行原子保存。保存失败不回滚当前界面，只在缩放控件附近显示“缩放设置保存失败，下次启动可能恢复默认值”。

视口壳层、所有固定控制区、内部滚动区和批量封面设置浮层必须在五档缩放下保持可操作。120% 与最小窗口组合是高度和换行压力最大的基准，但不能用只验证 80%、100%、120% 三个代表值代替完整五档验收。

## 7. 封面输入

每个游戏只保留当前一张封面。支持：

- 通过原生文件对话框选择 PNG、JPEG、WebP 或 BMP。
- 从浏览器剪贴板读取图片并以 PNG 数据提交。
- 替换已有封面。
- 移除封面，但不影响游戏记录。

本地原图只读导入，不移动、不覆盖也不删除用户源文件。剪贴板没有图片、权限被拒绝、文件损坏或超出限制时显示错误。

V0.3.6 增加全局“封面保存方式”，默认选择“自动优化（推荐，最长边 1920px）”，也可选择“保留原尺寸与格式”。游戏详情封面区和批量封面候选设置显示同一个明确下拉框，任一入口保存后同步并持久化；该设置只影响以后新采用或替换的封面，不批量改写已有文件。

## 8. 图片处理与存储

图片进入后端后执行：

1. 最多读取 50 MiB。
2. 根据实际解码格式验证，不信任扩展名或 MIME。
3. 限制单边最大 16,384 像素、总像素最大 6400 万。
4. 应用 EXIF 方向并转换为稳定颜色模式。
5. 按当前全局保存策略生成规范化原图。
6. 生成 400×600 的 WebP 2:3 居中裁剪缩略图。
7. 先写 `data/temp`，再移动到最终目录并更新数据库。

文件位置：

```text
data/covers/original/
data/covers/thumbs/
```

文件名包含游戏 ID、封面修订号和随机后缀，替换封面后 URL 随修订号变化，避免 WebView 缓存旧图。新文件或数据库更新失败时清理新文件并保留旧记录；成功后再删除旧受管文件。

“自动优化”应用于详情选择/粘贴、批量封面拖放/粘贴、浅层扫描、现成封面目录和 VNDB 等全部正式采用入口：

- 先应用 EXIF 方向，再按比例缩放，保证 `max(width, height) <= 1920`；横图限制宽度、竖图限制高度，不裁剪、不拉伸、不放大小图。
- 无透明通道保存为 JPEG，质量为 90；含透明通道保存为优化 PNG，不丢失透明背景。
- “保留原尺寸与格式”继续沿用当前规范化方式，不执行 1920 像素缩放或格式转换。
- 无论原图策略如何，网格缩略图继续独立生成 400×600 WebP；已有 `data/covers/original` 不在启动或设置切换时重处理。

## 9. 封面提供边界

前端不读取 `file://` 路径。封面通过带随机会话令牌的回环只读服务获取：

- 缩略图用于网格。
- 规范化原图用于详情。
- 游戏 ID 必须在数据库中存在对应封面记录。
- 解析后的文件必须仍位于受管封面目录。
- 外部任意路径不能通过 URL 参数读取。

## 11. 验收基准

- 大量游戏以响应式 2:3 网格显示，搜索和筛选只改变可见项。
- 游戏标题与版本号分开显示，版本为空时不留空白标签；搜索标题或版本号都能找到对应游戏。
- 无封面游戏显示稳定占位图，不产生损坏图片请求。
- 本地选择和粘贴截图都能设置封面。
- 游戏详情和批量封面的保存方式下拉框绑定同一全局设置；自动优化覆盖所有采用来源，关闭后保留原尺寸与格式，切换设置不改写已有封面。
- 自动优化后的横向 3840×2160 图片为 1920×1080，竖向 2160×3840 图片为 1080×1920；小图不放大，所有图片保持比例，透明图输出 PNG、普通图输出 JPEG。
- 非图片、损坏图片、超大文件和超大尺寸会被拒绝。
- 替换或移除封面不会修改用户原文件。
- 详情只显示一个关闭按钮。
- 点击遮罩、按 `Esc` 或点击关闭按钮都能关闭详情。
- 抽屉打开时主界面不滚动，抽屉内部可独立滚动。
- 抽屉打开和关闭不会因主滚动条消失而横向跳动。
- 焦点不会通过 Tab 移到被遮罩的主页面。
- 详情宽度正常情况下接近窗口的 40%，同时遵守 32rem 最小值、48rem 最大值和窄窗口 92vw 上限。
- 详情使用规范化原图并完整显示，不使用网格裁剪缩略图。
- 内容顺序为概览、封面、游戏设置、存档位置、自定义分组、游戏引擎、游戏记录。
- 游戏设置保留完整安装路径和主程序，并默认展开；路径可直接打开。
- 存档位置默认展开，查找存档仍需用户主动触发，规则设置默认折叠。
- 自定义分组位于存档位置之后并默认折叠；游戏引擎合并自动结果与手动设置并默认折叠；游戏记录位于底部并默认折叠。
- 关闭并重新打开详情后恢复固定默认折叠状态，不记忆上次状态。
- 缩放可在 80%～120% 间选择；重启和迁移整个便携目录仍能通过当前配置版本 5 恢复所选比例。
- 缩放配置保存失败不撤销当前比例，并显示下次启动可能恢复默认值的警告。
- 普通模式点击卡片打开详情；详情允许单独删除 `save_only` 卡片。主页批量删除只处理 `installed` 和 `missing`；V0.2 分组操作允许三种状态进入同一选择集合，但包含 `save_only` 时批量删除按钮必须禁用并指向详情或批量存档回退入口。
- 全选只加入当前筛选结果，切换筛选保留原选择；V0.2 正确统计已安装、失效和仅存档数量，删除摘要仍只处理前两类。
- 没有选择时批量删除不可用；最终确认准确说明两类记录处理语义和不删除用户文件的边界。
- 批量成功后只刷新一次游戏库并显示处理摘要；整批失败不留下前端“部分成功”状态。
- “批量选择”按钮在“游戏管理”组内原位置切换“批量选择”和“退出批量选择”，操作栏不重复提供退出按钮。
- “我的游戏”批量入口与下方搜索筛选栏之间保留稳定间距，按钮换行或界面缩放时不会贴在一起。
- 任意长宽比的详情原图都被约束在标题上方封面框内，不覆盖标题、快捷操作或封面操作区。
- 各缩放档位和窄窗口下不出现不可操作的横向溢出。
- `110%/120% + 960 × 640` 时搜索筛选工具栏切换为紧凑两行三列，“管理分组”入口保持可见且可操作，进入批量模式后游戏滚动区仍保留选择空间。
- 主页外层不产生页面级纵向滚动；应用顶栏、目录标题和游戏库控制区保持可见。
- 目录列表和游戏内容各自独立滚动，滚动到边界不带动另一侧或外层；搜索和筛选变化后游戏内容回到顶部。
- 所有五档缩放在最小、默认和宽屏窗口下均可操作，固定区不能把主要内容挤出可视范围。
- 所有自有滚动区使用统一深色滚动条；WebView2 不再显示白色轨道或箭头，系统回退不影响操作。
- V0.3.x 规则管理在正常宽度使用列表/详情双内部滚动，窄窗口使用列表与详情分步显示；五档缩放下固定工具栏和底部操作不覆盖唯一内容滚动区。
- 内置只读、用户编辑、未保存离开确认、外部点击关闭普通弹窗、危险操作确认、详情预填跳转和返回上下文恢复均有前端回归。
- 左侧固定扫描设置可以持久化启动快速核验开关和 1～4 全局并发；关闭启动核验后重启不提交 quick，禁用根目录不能手动扫描。
- quick 使用已知游戏总数显示确定进度；full 在发现阶段显示不确定进度，发现结束后按候选总数显示确定分析进度；所有活动阶段显示“已用时”，完成摘要区分业务统计与缓存复用统计并保留总耗时。
- 游戏设置中的重新检测可进入完成、失败或取消终态；成功刷新自动结果，任何终态都不覆盖人工设置或尚未保存的标题/版本输入。
- 分组筛选提供全部、未分组和具体分组，并与搜索、状态、引擎条件正确取交集；筛选变化回顶，删除当前分组后恢复全部。
- 分组管理支持新建、重命名和删除，显示成员数量；重名或保存失败保留编辑草稿，删除只清理关系。
- 详情可原子替换一个游戏的多个分组，失败不丢失勾选；批量加入/移出最多 500 个游戏并显示新增、移除和未变化数量。
- 分组管理浮层、详情多选和批量归组在 80%、90%、100%、110%、120% 以及最小、默认和宽屏窗口下无重叠或不可操作溢出。
- 批量归组和分组管理等普通模态浮层始终覆盖固定工具栏、卡片选择框和详情抽屉，底层控件不得显示在浮层之上。

## 12. 批量封面向导（已实现）

### 12.1 目标与入口

批量封面向导是模块 03 在 V0.1 收尾后的独立增强，不改变每个游戏只有一张当前封面的数据模型。“批量封面”位于窗口顶部全局一级导航；进入前关闭详情抽屉、普通模态并退出批量选择状态。

向导在当前 pywebview 窗口内作为一级工作区实现，不引入 Vue Router、不创建新的 Windows 窗口，也不清空主游戏库 Store。进入后游戏目录栏隐藏，工作台使用全局顶栏以下全部宽度；顶部“批量封面”保持选中，“游戏库”始终可见。离开前关闭后端会话并清理临时候选，返回后恢复进入前的搜索、筛选和滚动位置。

### 12.2 工作台布局与流程

常规窗口使用左右分栏：

- 左侧显示游戏队列、处理进度和每项状态。
- 右侧显示当前游戏、候选来源操作区、拖放区、统一候选画廊和审核操作。
- 游戏状态包括待处理、已有候选、已采用、已跳过和失败。
- 默认队列只包含没有封面的游戏；用户可切换为包含已有封面的游戏进行替换。
- 用户可以点击左侧任意游戏切换当前项。
- “采用并下一个”只有在选中候选时可用；保存成功后立即更新游戏库和队列，再进入下一项。
- “跳过并下一个”不修改封面，只记录当前会话内的跳过状态。

窄窗口或可用宽度不足时，左侧队列收起为顶部游戏选择器，候选画廊减少列数并允许纵向滚动，不能产生不可操作的横向溢出。工作台使用一级工作区语义；全局导航提供稳定返回路径，工作台内部不设置焦点陷阱或重复返回按钮。五档缩放都必须通过最小窗口验收，不能把 120% 视为唯一窄布局条件。

批量封面占满全局顶栏以下的剩余工作区，布局剩余行和内部滚动子项遵守与主页相同的 `minmax(0, 1fr)`、`min-height: 0` 收缩规则，工作台外层不再纵向滚动：

- 顶部“为游戏挑选封面”和候选设置固定；返回游戏库统一使用全局一级导航，不在工作台内重复放置返回按钮。
- 常规布局的左侧队列固定占满剩余高度；“包含已有封面”固定在顶部，只有下面的游戏队列滚动。队列条目分别显示标题、可选版本号和处理状态，并按自身内容高度排列；长标题换行或队列项目增多时不得压缩、重叠。
- 右侧当前游戏标题、启动游戏、候选来源按钮和任务进度固定；候选画廊是右侧唯一滚动区；“跳过并下一个”和“采用并下一个”固定在底部。
- 窄布局把队列替换为固定的游戏下拉框，不保留左侧队列滚动，因此工作台只剩候选画廊这一条主要滚动区域。
- 切换游戏、采用或跳过进入下一项时，候选画廊回到顶部；常规布局自动把当前队列项滚动到可视范围。

候选设置不再以内联展开内容挤压审核区。入口固定在当前游戏标题右侧，设置表单以锚定浮层向下覆盖候选区域；浮层限制在窗口内，最大高度约为可视高度的 70%，不足时只滚动浮层内部。点击外部或按 `Esc` 关闭并把焦点还给入口；浮层打开时第一次 `Esc` 不能退出整个工作台。未保存输入在关闭后保留，保存失败时浮层保持打开并显示错误，保存成功不强制关闭。浮层除联网和候选数量外，增加与详情共享的封面保存方式，以及 1～3 层的浅层扫描层数。

当前游戏标题旁提供“启动游戏”，复用详情页同一个 `launch_game` 接口。只有 `installed` 且存在主程序时可用；启动后不切换队列、不清空候选、不退出工作台也不自动最小化，成功或失败信息在按钮附近显示。窄窗口允许标题、版本和启动按钮安全换行，但不能产生横向滚动或压缩候选设置。

进入工作台时底层主页继续保留在 DOM 中但不可交互，目录和游戏内容滚动位置都不变化。退出后恢复原搜索、筛选和入口焦点，不再调用 `window.scrollTo()`。整个工作台仍可接收拖放，固定区域不能阻断为当前游戏添加候选。

### 12.3 会话式候选池

Python 使用独立的后端会话式候选池。一次向导会话包含游戏队列、当前游戏、候选元数据、来源状态和后台任务快照；同一时间只允许一个活动会话。会话只存在于内存和专用临时目录，不新增 SQLite 表，也不持久化未采用候选。

每个候选统一包含：

- 候选 ID 和所属游戏 ID。
- 来源类型与可读来源说明。
- 受保护的预览地址，不包含真实本地路径。
- 显示名称、图片尺寸和内容 SHA-256。
- 匹配等级、来源内部得分和可读匹配依据。

同一游戏中内容 SHA-256 相同的候选合并为一项，并保留全部来源依据。画廊先按来源优先级、再按匹配等级和来源内部得分排序。任何来源都不自动采用，模糊匹配和冲突必须由用户审核。

候选来源优先级固定为：

1. VNDB。
2. 拖放或剪贴板粘贴。
3. 用户手动触发的游戏目录浅层扫描。
4. 用户自定义选择的现成封面目录。

### 12.4 VNDB 在线候选

在线功能全局默认关闭。工作台顶部提供“允许在线搜索”开关，并明确说明只发送当前采用的纯游戏标题，不发送版本号、安装路径、安装目录名、数据库或本地文件。关闭后“搜索当前游戏”和“批量搜索在线候选”都不可用，也不能创建 VNDB 请求。

第一版只接入 VNDB Kana API：

- 查询当前游戏的 `title`，不拼接 `version`，并获取 VNDB 标题、别名、各语言标题和封面字段。
- 本地比较所有返回标题，区分精确、规范化精确和模糊匹配。
- 每个游戏默认保留搜索排名前 5 个带封面的结果，允许设置为 1～20。
- 批量搜索前显示待搜索游戏数并要求用户确认。
- 批量请求顺序执行，默认请求间隔 2 秒；遇到服务端限速响应时按服务端要求等待。
- 同一时间只运行一个 VNDB 搜索任务；搜索当前游戏也复用同一限速器。
- 只接受受控 VNDB HTTPS 图片域名，重定向后的最终地址也必须满足同一限制。
- 下载设置连接和读取超时、50 MiB 单图上限及解码尺寸上限，之后才把候选放入临时目录。
- 在线候选正常显示，不根据成人或暴力标记额外模糊图片。
- 候选保留 VNDB 条目 ID、标题和来源信息；程序不随发布包分发 VNDB 图片。

批量搜索支持进度、协作式取消和单项失败隔离。批量进度以“已完成的游戏数 / 本批游戏总数”为唯一计数口径；查询和下载单个游戏的多张候选时只更新当前说明，不能用候选图片数量覆盖批量计数。网络请求只发送纯标题；本地进度可以同时显示标题和版本号以区分队列项目。运行中显示“正在搜索 4/12：游戏名”一类当前状态，完成后保留 100% 完成状态，直到开始下一项来源任务或退出工作台。取消后已经完成的候选保留到本次会话结束，未开始的游戏恢复为待处理；用户仍需逐个审核，批量任务不能自动设置封面。

### 12.5 拖放与剪贴板候选

拖放和剪贴板只向当前游戏添加候选：

- 剪贴板继续支持 PNG 以及可转换为 PNG 的浏览器图片类型。
- 一次拖放最多接收 20 张图片，每张最多 50 MiB。
- 前端读取图片字节并通过受约束桥接提交，不传递或依赖浏览器暴露的本地绝对路径。
- 用户主动添加的候选不做标题模糊匹配，但仍经过格式、尺寸和解码验证。
- 添加候选不等于设置封面，仍需在画廊中选中并采用。

### 12.6 游戏目录浅层扫描

游戏目录扫描是低命中率的辅助入口，不因打开向导或切换游戏自动执行。只有用户点击“扫描当前游戏目录”时才扫描当前游戏。设置使用人类可读的总层数，避免把游戏安装目录和应用扫描根目录混淆：

- `1 层` 只扫描游戏安装目录本身；`2 层` 再包含直接子目录，等同升级前行为并作为默认值；`3 层` 再包含下一层子目录。
- 不跟随重解析点，不扫描超过所选层数的目录，不解包归档或商业游戏资源。
- 只考虑 PNG、JPEG、WebP 和 BMP，并复用现有图片安全限制。
- 根据竖向比例、有效分辨率、文件大小和文件名相关性综合排序；文件名匹配只作为加分项。
- 每个游戏默认保留 10 张，允许设置为 1～100。
- 层数只控制枚举范围，候选保留数量继续单独控制。枚举按目录名稳定排序，最多检查 5000 个图片文件，达到上限时明确标记结果已截断。
- 单张损坏、消失或不可读只产生单项警告，不中止其他候选。
- 扫描结束后必须显式上报确定的完成进度，不继续沿用运行中的动态进度。没有取得候选时显示“浅层扫描完成，未找到候选封面。”；取得候选时显示“浅层扫描完成，找到 N 张候选封面。”，两种结果的进度条都显示完成。

GARbro 等专用资源解包工具、资源解密和深层商业资源扫描不属于第一版范围。

### 12.7 自定义封面目录

“导入封面文件夹”面向用户已有的封面或截图目录，是最低优先级的可选来源：

- 每次由用户通过原生目录选择器自定义指定任意目录。
- 第一版只扫描所选目录本层，不递归，不跟随重解析点。
- 路径只用于当前向导会话，退出后不写入配置或数据库。
- 根据游戏标题、游戏安装目录末级名称和图片文件名匹配。
- 精确匹配优先；模糊匹配只生成候选，不能自动采用。
- 外部原图始终只读，不能移动、覆盖或删除。

### 12.8 配置、临时文件与采用边界

现已把便携配置从版本 2 升级为版本 3，新增以下字段，并继续原子写入程序旁 `data/config.json`：

| 字段 | 默认值 | 合法范围 |
| --- | --- | --- |
| `coverOnlineEnabled` | `false` | 布尔值 |
| `coverVndbCandidateLimit` | `5` | 1～20 |
| `coverLocalScanCandidateLimit` | `10` | 1～100 |

版本 2 迁移到版本 3 时必须保留现有 `uiScale` 和其他合法字段，再填入上述默认值；该配置迁移不涉及 SQLite。完整迁移与容错规则归入模块 01。

专用临时目录为 `data/temp/cover-wizard/<session-id>`：

- VNDB、拖放和粘贴候选在其中保存待采用原图与预览。
- 游戏目录和自定义封面目录中的外部原图只在后端会话内保存路径引用；安全预览放入临时目录。
- 临时候选通过带随机会话令牌的回环资源服务和候选 ID 提供，不能通过 URL 读取任意本地路径。
- 用户点击采用时才调用现有 `CoverService`；本地候选采用前重新验证路径、重解析点、文件身份和可读性。
- 每个游戏独立保存，不新增批处理数据库事务；采用失败时保留旧封面、当前选择和候选。
- 只有采用成功后才删除该候选所需的临时文件并清理旧受管封面。

退出向导时先请求取消后台任务并等待其进入终态，再清理未采用临时内容。程序正常关闭也执行同一清理；异常退出遗留的向导临时目录在下次启动时安全清理。再次进入向导时只根据游戏当前封面状态重建队列，不恢复上次候选或跳过状态。

### 12.9 错误、取消与关闭

- VNDB、浅层扫描和自定义封面目录导入等后台候选任务共用同一个醒目的进度区域。总数已知时显示语义化确定进度条、当前说明和完成数；总数未知时显示动态进度条。任务完成状态保留到下一项任务开始，失败时保留可读错误而不是只清空进度。

- 单个来源、单张图片或单个游戏失败不影响已经取得的候选和已采用封面。
- 来源错误显示在当前游戏及对应操作附近，并提供重试入口。
- 本地批量匹配和浅层扫描汇总损坏、不可读和截断数量，不为每张失败图片弹窗。
- 后台任务运行时退出向导，必须提示将取消搜索并清理未采用候选。
- 后台来源任务与当前审核游戏的候选列表请求使用彼此独立的前端修订号；任务运行中切换游戏只淘汰旧候选响应，不能停止任务轮询或把界面永久留在旧进度。关闭向导、重新打开会话或启动新任务时才使旧任务轮询失效。
- 关闭等待采用有界取消，不允许界面无限加载；清理不能与仍在写临时文件的任务并发。
- 应用断网、VNDB 超时或返回非法数据时，拖放、粘贴和本地来源继续可用。
- 采用过程中数据库或文件操作失败时沿用现有补偿语义，不得破坏旧封面。
- 候选设置保存失败时保留浮层、表单值和可读错误；外部点击关闭后重新打开仍保留本次尚未保存的输入。

### 12.10 已有封面队列标识（V0.3.4 已实现）

### 12.12 验收基准

- 从全局导航进入批量封面工作区并返回游戏库后，原搜索、筛选和滚动位置保持不变；封面临时候选已按会话关闭语义清理。
- 工作台外层没有页面级滚动条；常规布局只允许游戏队列和候选画廊各自滚动，窄布局只允许候选画廊滚动。滚动任一区域都不带动另一侧或底层主页；队列中的长标题可以自然换行且相邻游戏互不重叠。
- 顶部标题、当前游戏、候选来源及任务进度和底部审核按钮始终可见；候选设置以浮层展开，不改变画廊高度。
- 默认队列只包含无封面游戏；可显式包含已有封面游戏进行替换。
- 队列和当前游戏区域分别显示标题与可选版本号，版本号不与标题字段混存。
- VNDB 默认关闭，关闭时不产生网络请求；开启后的单项和批量请求都只包含纯标题，不包含版本号、安装路径、目录名或本地文件。
- 当前搜索和批量搜索都受限速、取消、超时和单项失败隔离约束。
- 所有后台候选任务都有明显进度反馈；VNDB 批量搜索的计数始终以游戏为单位，单个游戏的候选下载不能让总数或完成数跳回图片级计数。
- VNDB 批量搜索期间允许切换当前审核游戏；切换后任务进度继续轮询到终态，并刷新当前会话和所选游戏候选，不得停在切换前的游戏序号。
- 浅层扫描返回空候选时，任务状态、提示和进度条都明确表示已经完成，不显示“正在收集候选”或动态进度。
- 拖放、粘贴、浅层扫描和自定义目录候选进入同一画廊，按固定来源优先级排序。
- 游戏目录扫描只在用户点击后执行；层数可选 1～3，默认 2 层保持原行为，5000 图片上限、重解析点跳过和截断提示始终生效；自定义封面目录不递归且不持久化路径。
- 当前游戏可以从批量封面标题区直接启动；入口复用详情启动接口，不改变队列、候选、滚动或窗口状态，失效、仅存档和无 EXE 游戏不能启动。
- 外部原图不被移动、覆盖或删除，未采用候选不写数据库。
- 只有“采用并下一个”成功后才更新正式封面；失败时保留旧封面和当前审核上下文。
- 退出或取消不会留下活动任务；异常退出产生的专用临时目录能在下次启动清理。
- 80%、90%、100%、110%、120% 全部五档缩放，以及 `960 × 640`、`1180 × 760` 和宽屏窗口下均可完成选择、采用、跳过、取消和退出。
- 设置浮层在窗口范围内显示，外部点击和第一次 `Esc` 只关闭浮层并恢复焦点；保存失败不丢失输入。
- 队列、画廊和设置浮层使用统一深色滚动条，WebView2 不显示白色轨道或箭头。
- Python 测试覆盖匹配、去重、扫描边界、VNDB 解析与下载安全、限速取消、临时生命周期和采用补偿；前端测试覆盖队列、画廊、设置、任务进度和响应式交互。
