# GameSave Scout 开发路线图

> 文档性质：项目唯一有效的版本路线图与开发状态；最后更新：2026-08-25。

> V0.3.3 产品技术身份已在后端、前端、发布链和双版本便携候选中统一为 **GameSave Scout**，不保留旧运行入口；程序旁 `data` 与 schema 4 不变。完整门禁、冻结 smoke、六产物和独立完整性复核均已完成；旧版本真实产物、提交号和校验值保持原样。

## 1. 产品方向

GameSave Scout 是面向 Windows 10/11 x64 的本地优先、便携式个人游戏库与存档位置管理器，主要服务单机游戏、Galgame、DLsite 作品和 RPG Maker 等非平台统一管理的游戏。

项目不依赖 Steam 等平台导入。用户配置一个或多个游戏根目录，GameSave Scout 扫描目录建立游戏库，并允许用户维护封面、启动配置、引擎信息和存档位置。

## 2. 版本原则

- 先交付稳定的游戏库，再扩展复杂存档发现。
- 游戏发现不依赖引擎识别。
- 自动结果必须可解释，并允许用户纠正。
- 扫描与规则读取默认只读，不执行未知程序。
- 不在用户不知情时联网或扫描全盘。
- 所有自动发现都经过用户审核后才成为正式记录。
- 配置、封面、数据库和用户自定义规则都位于程序旁 `data`；内置规则随冻结资源发布。

## 5. V0.1 首发范围

### 已实现

- 多个用户指定游戏根目录。
- 直接子目录和 1～8 层递归扫描。
- 根目录排除规则和启用开关。
- 根目录设置编辑，以及已安装游戏“移除并忽略”和失效记录删除。
- 主页批量管理，支持跨筛选选择、全选当前结果、混合处理已安装/失效记录和一次事务提交。
- 可关闭的启动快速核验与手动完整扫描；新建根目录自动 full，禁用根目录不参与扫描。
- 持久化游戏分析缓存、按文件指纹和规则版本分层失效，以及单根/多根共享的 1～4 分析并发。
- quick 确定进度、full 发现/分析两阶段进度、当前目录、目录/发现/不可访问计数、耗时，以及业务与缓存分列的完成摘要。
- 游戏详情中的“重新检测主程序和引擎”，忽略缓存重建自动结果且不覆盖人工设置。
- 安装状态、移动建议和根目录重映射。
- 主 EXE 推荐、手动选择、参数、工作目录和环境变量。
- 游戏标题与可空版本号独立建模；新扫描只保守拆分明确的 `v`、`ver`、`version`、`build` 尾缀，两个字段分别保护人工修改和主动清空。
- 一张封面，支持本地选择和粘贴截图。
- 搜索、状态/引擎筛选，以及自适应 40% 宽度、独立分区和顶部快捷操作的右侧详情抽屉。
- 80%～120% 界面缩放，并通过程序旁的 `data/config.json` 跨启动和便携迁移保留。
- 主页 `100dvh` 视口壳层、目录与游戏内容独立滚动、固定控制区和统一深色滚动条。
- 批量封面向导的 VNDB、拖放/粘贴、浅层扫描和自定义非递归目录四类候选，以及队列/画廊独立滚动和锚定设置浮层。
- 游戏库、详情和批量封面队列独立显示版本号；本地搜索同时匹配标题与版本，VNDB 单项和批量搜索只发送纯标题。
- 第一批 Galgame、RPG Maker、Unity、Ren'Py 等引擎识别。
- VX Ace 解包结构、MV 双布局、Artemis 可变名称 PFS 和 Unreal Bootstrap/Shipping 正式检测。
- 引擎证据、歧义处理和手动覆盖。
- 每个游戏多个手动存档位置。
- 按需使用自定义清单、Ludusavi 和引擎提示查找存档。
- Ludusavi 本地三件套、摘要绑定 SQLite 索引、精确优先与模糊后备匹配、显式更新、按需恢复和失败降级。

V0.1 首发既定范围及其后的源码增强没有剩余强制开发或人工验收任务。自动门禁、本机人工验收、Windows Sandbox 主闭环与关键故障路径、历史双版本构建和冻结规则降级复验均已完成；游戏库扫描性能增强的 10 项人工验收也已全部通过。V0.1.4 已统一版本元数据和更新记录，并完成最新完整离线版、轻量联网版、ZIP、SHA-256 与分模式冻结复核，V0.1.x 收口完成。

## 7. V0.1：引导式寻找存档

引导式寻找存档属于 V0.1 首发范围，并且是发布门槛：

- 用户通过与静态查找分开的入口主动开始检测，全程序最多一个活动会话。
- GameSave Scout 先启动批准范围的 Win32 文件观察器，再使用现有配置启动游戏。
- 用户在游戏中保存后点击“我刚刚保存了”，约 3 秒后自动停止并分析。
- 程序聚合时间窗口内变化、过滤缓存和日志噪声；事件溢出时只对受影响范围受限补扫。
- 用户审核并接受候选位置。

它只在用户明确开始的单次会话中运行，不转变为常驻后台监控。防遗忘上限为 30 分钟，正常流程在保存标记后的约 3 秒等待结束后立即分析。实现细节、性能上限和隐私边界以模块 06 为准。

## 8. V0.2：自定义分组与批量存档发现

### 8.1 自定义游戏分组（V0.2.0 已完成）

- 用户创建、重命名和删除只有名称的扁平分组；第一版不做嵌套、颜色、图标或自动规则。
- 一个游戏可属于多个分组；分组适用于 `installed`、`missing` 和 `save_only`。
- 详情抽屉在存档位置下方提供默认折叠的分组区，并原子保存单游戏的全部分组；主页批量管理可把最多 500 个游戏加入或移出一个分组，标题栏按钮在原位置切换进入和退出状态。
- 主页提供“全部分组”“未分组”和具体分组的单选筛选，并与搜索、状态和引擎筛选取交集。
- 删除分组只删除关系，不删除游戏；扫描、失效、确认移动和重新检测不改变已有分组。
- 采用规范化关系表和固定数量的批量读取，不把名称数组写入 `games` 或 `config.json`。
- V0.2 使用新建 schema 3 数据库，不提供 V0.1 schema 2 迁移；检测到旧库时提示用户自行移走或删除，不自动破坏任何数据文件。

### 8.2 批量存档发现（V0.2.1 已完成）

- 用户从一级“批量存档”入口主动发起扫描；结果同时展示已安装游戏、失效游戏、未关联游戏、已记录、已忽略和不可用位置，待处理项优先排序，不把它限制成只看“孤立存档”的页面。
- 扫描采用规则优先的混合流程：先物化现有游戏、自定义清单、Ludusavi、引擎提示和显式注册表规则，再对 Documents、Saved Games、AppData 及用户选择的额外目录执行有深度、条目数和候选数上限的受限反向扫描；不递归游戏安装目录，不跟随重解析点。
- 为完整 Ludusavi 清单建立按路径特征反查作品的本地派生索引。唯一精确规则、稳定产品 ID 或明确清单条目可以形成高可信归属；模糊标题、目录名和引擎结构只作为可解释建议，不能自动确认。
- 候选按规范化类型与路径跨扫描复用，持久保存首次/最近发现、可用性、证据观察、人工关联、忽略和仅存档卡片状态。V0.2 后续使用全新 schema 4 数据库，不提供 schema 3 迁移；旧库在任何写入前拒绝并提示用户自行移走或删除。
- 用户可以审核后加入现有游戏、改关联、忽略或创建 `save_only` 卡片；批量接受只包含目标明确的候选，采用单事务全有或全无。任何流程都不读取、移动、重命名、修改或删除存档内容。
- 不自动抓取 DLsite、2DFan 或 VNDB。只有用户主动点击时，才把界面上可见的作品 ID 或推测关键词交给系统浏览器；完整本地路径、代表文件名和未展示信息不得发送。
- 工作台使用固定标题、进度和筛选区，结果区单独滚动；扫描设置点击外部关闭且保留本次范围；下拉条件自动应用，关键词使用 300ms 延迟；支持五档缩放、窄窗口、取消后保留不完整结果，以及清晰的不可访问和截断状态。

V0.2.0 已完成自定义分组源码和当时可操作范围的真实窗口验收。V0.2.1 已完成批量存档源码、正式 `save_only` 创建入口、自动端到端闭环和既定真实 pywebview 验收；当前完整门禁为 Python 858 项、前端 48 个测试文件共 193 项，并通过 Ruff、mypy、Vue 类型检查、115 模块生产构建和隔离 schema 4 源码 smoke。V0.1 引导式检测继续保持独立生命周期。

## 9. V0.3：引擎与存档规则扩展

### 9.1 V0.3.0 内置规则扩展（已完成）

- 已采用“双规则库 + 共享基础层”：引擎识别和存档位置规则保持独立结构，共用稳定 ID、来源、正式/实验状态、版本、公开依据、优先级、安全校验和诊断。
- 已校准 QLIE、Majiro、Malie、ShiinaRio、SoftPal/AmuseCraft、Entis/ERI/NOA、Nitroplus；除 SoftPal/AmuseCraft 因证据不足保持实验外，其余转正式，并新增 LiveMaker、CMVS/CVNS、Godot 三个正式规则。
- 已新增严格 `saves.yaml` 与统一提供者；首批正式通用规则覆盖 Godot、Unity、Unreal，Ren'Py、KiriKiri、NScripter、RPG Maker、WOLF 继续由受限代码提示提供证据，缺少可靠依据的引擎不猜路径。
- 详情静态查找只在用户点击后运行。GameSave Scout 不启动 Ludusavi 程序，只查询或按需内部重建其清单派生 SQLite 索引；实际存在与仅可推导路径分别展示并合并多来源证据。
- 批量扫描复用同一内置规则提供者，只接收实际存在的位置；新增 `builtin` 观察来源筛选，但接受后沿用 `engine` 持久来源。
- 已提供 `detect_directory.py --sanitized` 脱敏诊断。当前电脑缺少的真实游戏仍形成后续人工验收矩阵，不伪装成已经验证。
- 本阶段未新增持久业务表，未迁移 schema 4；内置规则只随 GameSave Scout 版本更新。

V0.3.0 完整源码门禁为 Python 963 项、前端 48 个测试文件共 197 项，并通过 Ruff、mypy、Vue 类型检查、115 模块生产构建和隔离 schema 4 源码 smoke；本轮未构建 V0.3.0 便携包。

### 9.2 V0.3.1 自定义规则编辑器（源码与真实窗口验收已完成，按需构建）

- 增加与游戏库、批量存档同级的独立“规则管理”工作台，使用“引擎规则”“存档规则”“Ludusavi”三个标签。正常宽度为左侧规则列表与右侧详情/编辑器，窄窗口改为列表和详情分步显示；顶部工具栏、底部主要操作固定，中间独立滚动。
- 内置规则只读，可查看、测试、本地启停和复制；用户规则一条一个 YAML，支持新建、修改、启停、复制、导入、导出和删除。第一版使用引导式表单与只读 YAML 预览，不开放任意文本、代码或脚本编辑。
- 用户规则覆盖引擎规则、游戏专属存档规则和引擎通用存档规则。游戏详情提供“为此游戏创建专属存档规则”入口，跳转并预填标题、产品编号、引擎和已确认存档位置；游戏专属规则只按精确身份匹配，不模糊自动归属。
- 新建和复制规则默认实验；成功只读测试后可由用户标记“用户规则 · 已验证”，修改身份匹配、证据或路径后自动回到实验。用户验证不等同于 GameSave Scout 官方验证。
- 文件是唯一事实来源，内置规则、用户规则和本地启停设置编译为不可变快照。每个任务开始时捕获快照；保存后只影响下一次任务，不自动重扫，外部修改通过“刷新规则”或重启加载。
