# GameShelf 开发路线图

> 文档性质：项目唯一有效的版本路线图与开发状态；最后更新：2026-08-17。

## 1. 产品方向

GameShelf 是面向 Windows 10/11 x64 的本地优先、便携式个人游戏库与存档位置管理器，主要服务单机游戏、Galgame、DLsite 作品和 RPG Maker 等非平台统一管理的游戏。

项目不依赖 Steam 等平台导入。用户配置一个或多个游戏根目录，GameShelf 扫描目录建立游戏库，并允许用户维护封面、启动配置、引擎信息和存档位置。

## 2. 版本原则

- 先交付稳定的游戏库，再扩展复杂存档发现。
- 游戏发现不依赖引擎识别。
- 自动结果必须可解释，并允许用户纠正。
- 扫描与规则读取默认只读，不执行未知程序。
- 不在用户不知情时联网或扫描全盘。
- 所有自动发现都经过用户审核后才成为正式记录。
- 配置、封面、数据库和可更新规则都位于程序旁 `data`。

## 5. V0.1 首发范围

### 已实现

- 多个用户指定游戏根目录。
- 直接子目录和 1～8 层递归扫描。
- 根目录排除规则和启用开关。
- 根目录设置编辑，以及已安装游戏“移除并忽略”和失效记录删除。
- 主页批量管理，支持跨筛选选择、全选当前结果、混合处理已安装/失效记录和一次事务提交。
- 启动快速核验与手动完整扫描。
- 扫描阶段、当前目录、目录/发现/不可访问计数、耗时和完成摘要。
- 安装状态、移动建议和根目录重映射。
- 主 EXE 推荐、手动选择、参数、工作目录和环境变量。
- 一张封面，支持本地选择和粘贴截图。
- 搜索、状态/引擎筛选，以及自适应 40% 宽度、独立分区和顶部快捷操作的右侧详情抽屉。
- 80%～120% 界面缩放，并通过程序旁的 `data/config.json` 跨启动和便携迁移保留。
- 第一批 Galgame、RPG Maker、Unity、Ren'Py 等引擎识别。
- VX Ace 解包结构、MV 双布局、Artemis 可变名称 PFS 和 Unreal Bootstrap/Shipping 正式检测。
- 引擎证据、歧义处理和手动覆盖。
- 每个游戏多个手动存档位置。
- 按需使用自定义清单、Ludusavi 和引擎提示查找存档。
- Ludusavi 本地三件套、摘要绑定 SQLite 索引、精确优先与模糊后备匹配、显式更新、按需恢复和失败降级。
- 独立的引导式寻找存档：单活动会话、先监控后启动、保存标记后约 3 秒分析、受限溢出补扫、可信度证据、事务式接受和全局状态恢复。
- 当前双版本 Windows x64 便携发布流水线：从同一无控制台 PyInstaller onedir 核心生成完整离线版与 `-lite` 轻量联网版；包含受控 Fixed Runtime/官方 Evergreen Bootstrapper、从项目 Conda 前缀确定性收集原生 DLL、格式版本 2 清单、双 ZIP/SHA-256、六产物原子发布和分模式冻结 smoke。轻量版手动安装引导已经实现；损坏规则降级修复后的六个当前候选已完成本机重建、独立自动复核和冻结副本复验，此前候选继续仅作为历史证据。

### V0.1 收尾结论

V0.1 当前范围没有剩余强制开发或验收任务。自动门禁、本机人工验收、Windows Sandbox 主闭环与关键故障路径、双版本重建和冻结规则降级复验均已完成。

完整目标 Windows 10/11 设备复核、Evergreen 已安装时断网启动、微软安装器断网/失败、UNC/只读目录/Fixed Runtime 损坏和 SmartScreen 实机提示没有完整执行，不记为已通过，统一转为后续版本可选兼容性复核，不再阻塞 V0.1。跨盘复制按范围决定不执行；完整发布负载绝对路径达到或超过 260 字符明确不受 V0.1 支持。

## 6. V0.1 明确不包含

- 常驻后台文件监控。
- 启动任意游戏时自动抓取全电脑文件变化。
- 删除游戏后的孤立存档反推。
- 存档备份、恢复、同步和云服务。
- 对接 Steam、Epic、GOG 或其他平台账号。
- 自动联网下载封面或游戏元数据。
- 游戏翻译、注入、Hook 或修改游戏文件。
- 安装器、自动更新器和公开 Release 自动发布。

## 7. V0.1：引导式寻找存档

引导式寻找存档属于 V0.1 首发范围，并且是发布门槛：

- 用户通过与静态查找分开的入口主动开始检测，全程序最多一个活动会话。
- GameShelf 先启动批准范围的 Win32 文件观察器，再使用现有配置启动游戏。
- 用户在游戏中保存后点击“我刚刚保存了”，约 3 秒后自动停止并分析。
- 程序聚合时间窗口内变化、过滤缓存和日志噪声；事件溢出时只对受影响范围受限补扫。
- 用户审核并接受候选位置。

它只在用户明确开始的单次会话中运行，不转变为常驻后台监控。防遗忘上限为 30 分钟，正常流程在保存标记后的约 3 秒等待结束后立即分析。实现细节、性能上限和隐私边界以模块 06 为准。

## 8. V0.2：孤立存档发现

- 扫描已知 AppData、LocalLow、Documents、Saved Games 和 Ludusavi 位置。
- 支持用户选择额外目录进行受限扩展扫描。
- 尝试给出游戏名或引擎建议，但不保证准确反推。
- 用户可关联现有游戏、创建仅存档卡片或忽略。
- 不读取或修改存档内容。

V0.1 引导式检测和 V0.2 孤立存档是独立子项目；不因为共享部分数据表就合并实施。

## 9. V0.3 及以后

候选方向：

- 存档备份与恢复。
- 版本历史与完整性校验。
- 可选的外部目录同步。
- 游戏库导入/导出。
- 更完善的自定义引擎与存档规则编辑器。
- 在线封面或元数据提供者，但必须显式启用并有缓存/隐私设计。

这些功能在前一版本稳定前不提前实施。

## 10. 质量门禁

每个代码增量按风险运行相关测试；首版候选发布必须在项目根目录激活包含 Python 3.12 与 Node.js 24 的 Conda 环境后运行：

```powershell
conda activate .\.venv
python -m pytest
python -m ruff check src tests
python -m mypy src
npm --prefix frontend run test:unit -- --run
npm --prefix frontend run type-check
npm --prefix frontend run build
python -m gameshelf --smoke-test
```

正式冻结产物必须运行模块 07 定义的冻结冒烟；额外干净目标设备复核属于后续可选兼容性检查。
