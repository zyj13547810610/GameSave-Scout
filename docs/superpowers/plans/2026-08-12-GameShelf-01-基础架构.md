# GameShelf 基础架构

> 文档性质：当前有效的模块设计与验收基准；适用版本：V0.1 及后续迭代；最后更新：2026-08-13；状态：基础能力已实现。

## 1. 模块目标

本模块提供 GameShelf 其余功能共同依赖的桌面外壳、便携数据目录、SQLite 数据库、后台任务、前后端桥接和本地资源服务。

基础架构必须满足三个核心要求：

- Windows 10/11 x64 上可运行。
- 程序目录与 `data` 可以整体迁移。
- 扫描、清单更新等耗时操作不能阻塞界面。

## 2. 技术栈

| 层级 | 当前选择 |
| --- | --- |
| 桌面容器 | pywebview |
| 后端 | Python 3.12 |
| 前端 | Vue 3、TypeScript、Vite、Pinia |
| 数据库 | SQLite |
| 图片处理 | Pillow |
| 引擎规则 | PyYAML、pefile |
| 模糊匹配 | RapidFuzz |
| Python 测试 | pytest |
| 前端测试 | Vitest、Vue Test Utils、jsdom |
| 静态检查 | Ruff、mypy、vue-tsc |

选择 pywebview 方案的原因是前端布局和交互迭代更灵活，同时 Python 适合 Windows 文件系统、注册表、进程和 SQLite 操作。前后端边界通过显式桥接 API 维持，不让网页直接访问任意本地文件。

## 3. 启动与关闭流程

程序启动时按以下顺序组装：

1. 从源码目录或冻结版可执行文件旁确定程序根目录。
2. 创建并验证程序旁的 `data` 目录可写。
3. 初始化日志、SQLite 连接和数据库迁移。
4. 启动单一数据库写入线程与后台任务池。
5. 组装游戏库、扫描、启动、封面、引擎和存档服务。
6. 在 `127.0.0.1` 随机端口启动只读资源服务。
7. 创建 pywebview 窗口并注入桥接对象。

关闭时停止后台任务、数据库写入线程和本地资源服务。新后台任务在关闭开始后不得继续提交。

## 4. 便携目录

所有由 GameShelf 管理的持久数据都位于程序旁的 `data`：

```text
GameShelf/
├─ GameShelf.exe                 # 冻结版；源码运行时不存在
├─ resources/
│  ├─ ui/
│  ├─ rules/
│  └─ manifests/ludusavi/
└─ data/
   ├─ library.db
   ├─ config.json
   ├─ covers/
   │  ├─ original/
   │  └─ thumbs/
   ├─ manifests/
   ├─ webview/
   ├─ db_backups/
   ├─ logs/
   └─ temp/
```

路径解析不能依赖当前工作目录。冻结版以 `sys.executable` 所在目录为根，源码版以仓库根目录为根。

如果程序目录不可写，启动必须明确失败并提示用户把整个目录移动到可写位置，不能悄悄改用 AppData。临时文件只放在 `data/temp`，写入完成后再原子替换目标文件。

## 5. 配置管理

`data/config.json` 使用带版本号的 UTF-8 JSON。当前字段包括：

| 字段 | 含义 |
| --- | --- |
| `version` | 配置结构版本，当前为 1 |
| `language` | 界面语言，当前默认 `zh-CN` |
| `startupQuickScan` | 计划控制启动后的快速扫描 |
| `orphanScanExclusions` | 后续孤立存档扫描的全局排除项 |

配置保存采用临时文件加原子替换。未知字段、不支持的版本或类型错误必须报告为配置无效，并保留原文件供用户手动恢复。

配置存储结构已经实现，但当前应用尚未把 `startupQuickScan` 等字段接入设置界面和启动流程；前端现在会对所有已启用根目录执行快速扫描。

界面缩放当前存储在 WebView 的 `localStorage`，不在 `config.json` 中；程序目录迁移后是否保留缩放值取决于 WebView 数据目录和页面来源。未来应将其迁入统一配置。

## 6. SQLite 数据与迁移

当前数据库版本为 1，包含：

- `scan_roots`：多个游戏扫描根目录及各自规则。
- `games`：游戏库、启动配置、封面和引擎结果。
- `save_locations`：已确认的存档位置。
- `scan_sessions`、`scan_observations`：扫描会话与临时观察结果。
- `save_detection_sessions`、`save_discoveries`：为后续动态和孤立存档发现预留的数据结构。
- `settings`：可扩展的键值设置。

迁移规则：

- 按版本顺序执行 SQL 文件。
- 数据库版本高于程序支持版本时拒绝打开。
- 已有用户表升级前先备份完整 SQLite 数据库。
- 迁移失败时回滚，错误中给出备份位置。
- 最多保留最近 5 份迁移前备份。

所有写操作通过一个专用写入线程串行执行；普通列表和查询使用短生命周期只读连接，避免跨线程复用 SQLite 连接。

## 7. 后台任务

扫描和 Ludusavi 更新使用统一 `TaskRegistry`：

- 状态：`queued`、`running`、`completed`、`cancelled`、`failed`。
- 进度包含已完成数量、可选总量和当前阶段消息。
- 前端通过任务 ID 轮询快照。
- 取消是协作式取消；任务在安全检查点响应。
- 未捕获异常写入 `data/logs/gameshelf.log`，前端只收到稳定、可读的错误提示。

任务池当前最多同时运行 2 个任务。需要修改数据库的任务仍通过单一写入线程提交事务。

## 8. 前后端桥接

桥接统一返回以下两种结构之一：

```text
成功：{ ok: true, data: ... }
失败：{ ok: false, error: { code, message, details? } }
```

约束：

- 前端不接收 Python 对象，只接收可序列化 DTO。
- 请求字段在后端重新校验，不能信任 TypeScript 类型。
- 业务错误使用稳定错误码，避免前端解析异常字符串。
- 文件和目录选择由原生对话框完成。
- 前端不能传入任意路径要求后端读取或提供文件内容。

## 9. 本地资源服务

前端生产文件和封面通过一个只读 HTTP 服务加载：

- 只绑定 IPv4 回环地址 `127.0.0.1` 和随机端口。
- 每次启动生成随机会话令牌，令牌位于 URL 路径中。
- 只开放 UI 和已由数据库关联的封面路由。
- 封面路径必须位于受管的 `data/covers` 目录。
- 响应带有限制性 CSP，不提供目录列表和任意文件读取。

开发时可使用 `GAMESHELF_DEV_SERVER_URL` 指向 Vite；冻结版忽略该变量并始终加载随包 UI。

## 10. 错误处理与日志

- 用户可处理的问题直接显示中文消息。
- 无法访问扫描根目录不改变已有游戏状态。
- 后台任务异常写入日志，并结束加载状态。
- 数据库、配置或资源初始化失败时不继续启动半可用程序。
- 日志不得主动记录存档文件内容、剪贴板图片内容或环境变量值。

## 11. 代码职责

| 区域 | 主要职责 |

| `src/gameshelf/bootstrap` | 路径、配置、日志和应用组装 |

## 12. 验收基准

- 源码运行和冻结版都从正确的程序根目录解析资源与 `data`。
- 整个程序目录移动后，数据库、封面和规则仍可读取。
- 不可写目录会在启动阶段给出明确错误。
- 配置写入和数据库迁移失败不会留下被当作有效文件的半成品。
- 并发后台任务不会直接并发写 SQLite。
- 任务成功、失败和取消后都能进入终态，界面不会永久加载。
- API 对缺字段、错误类型和越界路径返回稳定失败结构。
- 本地资源服务无法读取白名单之外的文件，也不监听局域网地址。
- Python 与前端的自动化测试、类型检查和构建命令可独立执行。
