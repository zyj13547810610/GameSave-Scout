# GameShelf 便携版打包与发布

> 文档性质：待实施模块设计与发布基准；适用版本：V0.1 首个可分发版本；最后更新：2026-08-13；状态：源码运行和便携数据路径已完成，正式 PyInstaller 产物尚未实现。

## 1. 发布目标

产出 Windows 10/11 x64 可直接解压运行的 onedir 便携包：

- 用户不需要安装 Python、Node.js 或项目依赖。
- 配置、数据库、封面、清单、日志和 WebView 数据都位于程序旁的 `data`。
- 整个目录可以复制到其他本地磁盘位置继续使用。
- 完整包包含可用的 WebView2 方案，不依赖开发工具。
- 发布物包含许可证、第三方声明、版本和可验证哈希。

首版只制作 onedir，不制作 onefile 和安装器。onedir 更适合大体积 WebView2、清晰的数据目录和可诊断的资源结构。

## 2. 当前已具备基础

- 冻结模式下 `data` 根目录会解析到 `GameShelf.exe` 所在目录。
- 源码和冻结模式都不依赖当前工作目录。
- Vue 生产构建可生成到 `resources/ui`。
- `python -m gameshelf --smoke-test` 可无窗口启动应用、初始化数据库并关闭资源。
- pywebview 的存储目录已经指向 `data/webview`。
- CI 在 Windows 上运行 Python 测试、Ruff、mypy、前端测试、类型检查和构建。
- 第三方声明文件和 Ludusavi 许可证已经存在。

尚未具备：

- PyInstaller 依赖和 `.spec`。
- 正式构建脚本及构建输入校验。
- 固定版 WebView2 下载、校验和暂存。
- 冻结产物自动化测试。
- 发布清单、压缩包哈希和干净虚拟机验收。

## 3. 目标目录结构

```text
GameShelf/
├─ GameShelf.exe
├─ _internal/                   # PyInstaller Python 与不可变资源
├─ runtime/                     # 完整包的固定版 WebView2
├─ data/                        # 首次运行创建，可整体迁移
├─ README.txt
├─ LICENSE
├─ THIRD_PARTY_NOTICES.md
└─ release-manifest.json
```

不可变 UI、引擎规则和内置 Ludusavi 种子随 `_internal` 打包；可更新清单和用户数据只写到 `data`。固定版 WebView2 位于可执行文件旁的 `runtime`，不写入 `_internal`。

## 4. 资源解析

正式打包前需要把资源路径统一到一个只读 `ResourcePaths`：

- 源码模式：仓库根目录下的 `resources`。
- 冻结模式：`sys._MEIPASS/resources` 或 PyInstaller onedir 对应内部目录。
- 固定版 WebView2：始终位于 `GameShelf.exe` 旁的 `runtime`。
- 可写数据：始终位于 `GameShelf.exe` 旁的 `data`。

启动时应一次性验证 UI、引擎规则和内置 Ludusavi 种子是否齐全，缺失时报告逻辑资源名称，而不是只显示 traceback。

## 5. 构建流水线

建议使用 PowerShell 入口脚本，按以下顺序执行：

1. 验证 Windows x64、Python 3.12、Node 24、锁文件和仓库路径。
2. 使用 `npm ci` 安装锁定前端依赖。
3. 运行前端测试、类型检查和生产构建。
4. 以安全暂存方式更新 `resources/ui`。
5. 运行 Python 测试、Ruff 和 mypy。
6. 使用经过审查的 PyInstaller `.spec` 构建 onedir。
7. 下载或复用固定版 WebView2，校验版本与 SHA-256 后暂存到 `runtime`。
8. 写入发布清单和许可证文件。
9. 对构建目录副本执行冻结版冒烟测试。
10. 生成 zip 和 SHA-256 文件。

构建脚本替换 `resources/ui` 或 `dist/GameShelf` 前，必须解析并断言目标精确位于仓库内，不能对未经验证的变量执行递归删除。

## 6. PyInstaller 约束

- 目标架构仅 x64。
- 使用 onedir 和无控制台窗口入口。
- 显式收集 pywebview 后端、Pillow 插件、PyYAML、pefile、证书及项目资源。
- 不把运行时生成的 `data` 打进 `_internal`。
- Python 包版本与 `GameShelf.__version__` 一致。
- 构建产物不得依赖开发机器的绝对路径、虚拟环境或当前工作目录。
- 不从系统 PATH 查找项目资源。

冻结版应支持结构化冒烟输出，例如：

```json
{
  "ok": true,
  "appVersion": "0.1.0",
  "schemaVersion": 1,
  "frozen": true,
  "appRoot": "D:\\GameShelf",
  "dataDir": "D:\\GameShelf\\data"
}
```

当前 `--smoke-test` 只有文本输出；打包阶段应增加 `--json`，并保持旧文本模式可用。

## 7. WebView2 策略

完整便携包优先包含 Microsoft Fixed Version WebView2 Runtime x64：

- 版本和下载 SHA-256 固定在受版本控制的清单中。
- 二进制体积较大，不提交到 Git。
- 下载只使用官方 HTTPS 地址，并在解压前校验哈希。
- WebView 用户数据固定到 `data/webview`。
- Windows 10 上按官方要求验证运行时目录读取/执行权限。

固定版 WebView2 不能从 UNC/网络路径可靠运行。程序检测到网络路径时，应尝试已安装的 Evergreen Runtime；两者都不可用时显示可操作错误。首版“目录可迁移”指本地文件系统路径，不承诺直接从网络共享运行。

可以另行生成不含固定运行时的较小开发包，但不能把它标为完整离线便携版。

## 8. 数据迁移与复制一致性

用户复制正在运行的目录可能得到不一致的 SQLite WAL 或半写文件。帮助文本应要求先退出 GameShelf 再复制整个目录。

正式验收需要验证：

- 退出后复制目录，数据库和配置保持完整。
- 含中文、日文和空格的本地路径可运行。
- 从一个盘符移动到另一个盘符后，程序自身数据正常；游戏根目录需要时可重映射。
- 缺少或损坏 `data` 子目录时能安全重建空目录，不覆盖现有有效数据。
- 数据库升级先生成备份。

## 9. 发布元数据

`release-manifest.json` 至少记录：

- 应用版本和构建时间。
- Git 提交号。
- Python、Node、PyInstaller 和 pywebview 版本。
- 数据库架构版本。
- 引擎规则版本。
- Ludusavi SHA-256 和上游提交号（如有）。
- WebView2 版本和归档 SHA-256。
- 构建架构和是否包含固定运行时。

压缩包旁发布独立 SHA-256。未经用户明确决定，不自动创建公开 Release，也不代替用户选择开源许可证。

## 10. 干净环境验收

最终发布前在没有开发环境的 Windows 10 和 Windows 11 x64 环境验证：

- 无 Python、Node 和 Visual Studio 也能启动。
- 没有系统 WebView2 时，完整包使用随附运行时。
- 首次启动在程序旁创建 `data`。
- 添加根目录、扫描、启动、封面、引擎和手动存档位置正常。
- 退出后复制整个目录到新的本地路径仍可使用。
- 中文/日文路径、离线环境、断网更新失败和只读目录错误符合设计。
- 卸载只需退出后删除整个目录，不在系统其他位置遗留 GameShelf 自有数据。

## 11. 安全与供应链

- 构建依赖使用锁文件或明确版本范围。
- WebView2 只从官方来源下载并校验哈希。
- 发布前生成软件清单和第三方声明。
- 构建日志不能包含用户本地游戏路径或数据目录内容。
- 不把商业游戏、用户封面、存档或本地 `data` 打进发布物。
- 构建脚本不得上传产物，发布是单独且需要授权的操作。

## 12. 验收基准

- `dist/GameShelf/GameShelf.exe` 可在干净 Windows 10/11 x64 启动。
- 产物为 onedir，不是 onefile。
- 完整包在没有预装 WebView2 的离线环境可用。
- 冻结版所有持久写入都在程序旁 `data`。
- 复制后的产物使用新位置旁的 `data`，不回写旧目录。
- 构建和发布清单中的版本、哈希与实际文件一致。
- UI、引擎规则、Ludusavi 种子和许可证都包含在产物中。
- 构建前完整质量门禁通过，冻结产物冒烟测试也通过。
- 网络路径和不可写目录给出明确错误，不静默回退到其他用户目录。
