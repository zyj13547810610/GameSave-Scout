# V0.3.6 批量封面共享候选池实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把“导入封面目录”改为短生命周期共享候选池，使 hash、UUID 和截图编号图片都能由用户逐游戏人工采用，并修复零新增任务错误显示为仍在收集的问题。

**Architecture:** Python 继续独占文件系统和图片处理；`LocalCoverDiscovery` 只负责有界、非递归地导入并暂存共享图片，`CoverWizardService` 负责会话池、动态按游戏投影、使用记录和采用事务。桥接 API 显式传递 `includeUsed` 与 `gameId`，Vue/Pinia 只维护当前会话视图和“显示已使用图片”开关；共享池不进入 SQLite 或配置。

**Tech Stack:** Python 3.12、Pillow、RapidFuzz、pywebview、Vue 3、Pinia、TypeScript 5.9、Vitest、pytest、Ruff、mypy、Vite。

**Spec:** `docs/superpowers/specs/2026-08-28-V0.3.6-批量封面共享候选池设计.md`

## Global Constraints

- 产品版本保持 `0.3.6`，Python 要求保持 `>=3.12,<3.13`，Node.js 要求保持 `>=24,<25`。
- SQLite schema 保持 4，配置版本保持 6；不得新增数据库迁移、候选表或持久共享池。
- 导入目录只读且非递归；不得修改、移动或删除用户原图，不得读取非图片文件，不得联网。
- 图片安全边界保持单文件 50 MiB、最长边 16,384 像素、最多 64,000,000 像素、预览最大 480×720。
- 单个会话最多保留 1,000 张内容唯一的共享图片，最多检查 5,000 个受支持图片文件；达到边界必须报告截断。
- 所有图片仍需用户逐项采用；文件名匹配只排序，不得过滤低分、hash、UUID 或截图编号图片。
- 共享图片采用后默认隐藏，但必须可通过“显示已使用图片”查看并复用；外部原图始终保留。
- 只有显式构造的安全任务错误可以把业务消息返回前端；其他异常继续隐藏内部细节并写入日志。
- `resources/ui` 只能通过 `npm --prefix frontend run build` 生成，不得手改带 hash 的产物。
- 开始实施前完整阅读本计划和关联规格；每个任务只提交列出的范围，不夹带重构或便携包构建。

```python
class TaskFailure(RuntimeError):
    """A deliberately user-safe background-task failure."""

    def __init__(self, code: str, message: str) -> None:
        if not code.strip() or not message.strip():
            raise ValueError("任务失败代码和消息不能为空。")
        super().__init__(message)
        self.code = code
        self.message = message
```
