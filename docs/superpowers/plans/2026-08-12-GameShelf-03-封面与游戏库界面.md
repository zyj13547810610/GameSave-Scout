# GameShelf 封面与游戏库界面

> 文档性质：当前有效的模块设计与验收基准；适用版本：V0.1；最后更新：2026-08-14；状态：现有功能、详情抽屉重排、缩放持久化和主页批量管理已实现。

## 1. 模块目标

主界面以封面网格展示游戏库，并提供搜索、筛选、根目录管理和右侧游戏详情。每个游戏只设置一张封面，可从本地文件选择或直接粘贴剪贴板截图。

界面优先保持游戏库浏览上下文：打开详情时不切换整页，关闭后回到原卡片位置。

## 2. 主界面布局

主界面由以下区域组成：

- 顶栏：应用标题、界面缩放和添加游戏目录。
- 左侧栏：多个扫描根目录及扫描操作。
- 内容区：游戏数量、移动建议、搜索和筛选工具栏、封面网格。
- 详情层：选中游戏后从右侧显示的模态详情抽屉。

游戏网格使用响应式 CSS Grid。窗口或界面缩放改变时，浏览器根据可用宽度自动调整每行卡片数量；游戏数据和图片组件不会因此重新请求或重复创建整份游戏库。

## 3. 游戏卡片

每张卡片显示：

- 2:3 封面缩略图；没有封面时显示标题首字符占位图。
- 游戏标题。
- 安装状态。
- 已识别或手动设置的引擎标签。

卡片标题允许省略显示，但保留完整文本提示。点击卡片打开详情，键盘焦点进入抽屉；关闭后焦点返回原卡片。

主界面支持：

- 按标题即时搜索。
- 按 `installed`、`missing`、`save_only` 状态筛选。
- 按当前采用的引擎筛选。
- 无游戏、无搜索结果、连接失败和扫描错误等独立状态。

### 3.1 主页批量管理

“我的游戏”标题右侧增加中性的“批量管理”按钮。进入批量模式后：

- 已安装和本体失效卡片左上角显示复选框；点击卡片任意区域切换选择，不打开详情。
- 选中卡片使用明显边框和半透明高亮，同时保留键盘焦点样式。
- `save_only` 卡片不显示可用复选框且不能进入选择集合。
- 搜索、状态和引擎筛选继续可用；切换筛选不会清除此前选中的隐藏项目。
- “全选当前结果”只把当前筛选后可见且允许批量处理的卡片加入选择，不移除其他已选项目。

批量模式下始终显示操作栏，内容包括：已选择总数、其中已安装/失效数量、全选当前结果、清空选择、退出批量管理和删除所选。没有选中项目时“删除所选”不可用；退出批量模式会清空选择。

最终确认框分别说明两类结果：已安装项目会从库中移除并加入各自根目录精确排除项；失效项目会删除数据库记录。确认框同时明确不会删除游戏文件、外部存档或用户原始封面。

成功后前端清空选择、退出批量模式、只刷新一次游戏库，并显示已安装处理数、失效处理数、更新根目录数及封面清理警告摘要。整批验证失败或记录状态变化时不显示部分成功，刷新游戏库后要求用户重新选择。

## 4. 详情抽屉

详情抽屉固定在窗口右侧，拥有自己的纵向滚动区域。当前实现宽度为：

```css
width: clamp(32rem, 40vw, 48rem);
max-width: 92vw;
```

正常窗口下以主窗口可视宽度的 40% 为目标；较窄窗口受 32rem 最小可用宽度约束，特别窄时再由 `max-width: 92vw` 限制；超宽窗口不超过 48rem。界面缩放仍通过现有 `rem` 体系影响最小和最大宽度。

### 4.1 内容顺序与视觉层级

详情内容固定按以下顺序排列：

1. 顶部概览。
2. 封面操作。
3. 游戏设置。
4. 存档位置。
5. 游戏引擎。
6. 游戏记录。

游戏设置和存档位置是主要工作区，使用正常强调的卡片；游戏引擎是低频诊断区；游戏记录是最底部的危险操作区。各功能区独立展开，不使用“展开一个便自动关闭另一个”的手风琴限制。

每次打开详情恢复固定默认状态，不跨游戏、不跨关闭操作记忆折叠状态：

- 游戏设置、存档位置默认展开。
- 游戏引擎、游戏记录默认折叠。
- 高级启动设置、存档位置高级信息、存档规则设置默认折叠。

### 4.2 顶部概览与封面

顶部采用居中大封面方案：

- 详情始终请求规范化原图，使用 `object-fit: contain` 完整显示，不进行 2:3 裁剪。
- 封面框居中，高度使用 `min(22.5rem, 46vh)`：常规窗口保留现有大封面上限，低高度窗口自动缩短；无封面时继续显示稳定占位图。
- 封面下依次显示完整标题、安装状态和当前采用的引擎标签。
- “启动游戏”作为主操作，“打开安装目录”作为次操作，均放在顶部快捷区。
- 紧接概览的是封面操作栏，提供选择/替换本地图片、粘贴截图和移除封面。

顶部快捷操作不取代后续设置内容。安装路径和主程序仍在游戏设置中完整显示。

### 4.3 游戏设置

游戏设置默认展开，包含：

- 可编辑标题及保存操作。
- 完整安装路径以可点击路径控件显示，点击后进入该目录。
- 当前主程序相对路径及“选择/重新选择主程序”。
- 默认折叠的高级启动设置：工作目录、参数和环境变量。

顶部已经提供启动和打开目录快捷操作后，游戏设置不再重复放置另一个独立“打开文件夹”按钮；安装路径控件本身仍可点击打开。

### 4.4 存档位置

存档位置默认展开：

- 标题行放置“手动添加”和“全部验证”。
- 已确认位置按卡片显示；路径本身可点击打开。
- 来源、可信度、确认状态和是否存在使用紧凑标签表达。
- 路径模板与识别依据放在每张位置卡片的“高级信息”内。
- “查找存档位置”只在用户主动点击后执行并显示结果，不因打开详情自动扫描。
- Ludusavi 状态、清单更新和自定义目录位于默认折叠的“存档规则设置”中。

### 4.5 游戏引擎

现有自动识别结果与手动引擎设置合并成一个默认折叠的“游戏引擎”卡片：

- 折叠标题显示当前引擎、自动/手动状态和可信度。
- 未知或歧义结果在折叠标题显示黄色状态，但不自动展开。
- 展开后显示当前采用值、最近自动检测结果和手动引擎选择。
- 识别证据作为内部二级折叠项。

### 4.6 游戏记录

游戏记录位于最底部并默认折叠，使用暗红边框和弱红色背景；只有最终危险按钮使用明显红色：

- 已安装游戏提供“从库中移除并忽略”。
- 本体失效游戏提供“删除失效记录”。
- 说明文本必须明确不会删除游戏本体或外部存档。
- 执行前继续要求二次确认。

### 4.7 关闭方式

抽屉只保留右上角一个关闭按钮，并支持：

- 点击左侧半透明遮罩关闭。
- 按 `Esc` 关闭。
- 关闭后恢复打开详情的卡片焦点。

抽屉内普通空白区域不关闭，避免编辑表单时误操作。

### 4.8 滚动行为

- 抽屉打开时锁定主页面滚动。
- 主页面滚动条占用的宽度通过 `body` 右侧补偿，避免内容横向跳动。
- 遮罩拦截滚轮，不让左侧页面随详情滚动。
- 抽屉内部独立滚动，并使用 `overscroll-behavior` 阻止滚动链传回主页面。
- 抽屉滚动条位于抽屉内部，不与主界面滚动条并排显示。

### 4.9 网格策略

打开抽屉时，主界面网格不为抽屉重新缩窄和重排。抽屉以覆盖层形式显示，左侧加 22% 黑色半透明遮罩。

选择覆盖方案的原因：

- 用户打开详情时主要关注当前游戏，不需要同时操作网格。
- 不会因网格列数变化造成卡片大幅移动。
- 大型游戏库不发生额外布局抖动。
- 点击遮罩即可清楚返回游戏库。

### 4.10 加载、错误与数据行为

- 重排只改变展示结构，不新增自动扫描、网络访问或游戏目录读取。
- 折叠和展开不销毁区块数据，也不重复请求整份游戏详情。
- 封面、标题、启动、存档、引擎和记录操作继续在各自区块附近显示忙碌状态与错误；顶部快捷操作失败时在快捷区显示可读错误。
- 关闭详情会清除临时错误和折叠状态；不会清除已经成功保存的游戏数据。
- 组件测试覆盖内容顺序、默认折叠状态、顶部快捷操作、原图 URL、路径打开以及安装/失效两类危险操作。
- 人工响应式验收至少覆盖 80%、100%、120% 界面缩放，以及窄窗口、常规窗口和 1920px 宽窗口。

## 5. 键盘与可访问性

- 抽屉使用 `role="dialog"` 和 `aria-modal="true"`。
- 打开后把焦点移入抽屉。
- `Tab` 和 `Shift+Tab` 在抽屉可聚焦元素间循环。
- `Esc` 与关闭按钮行为一致。
- 图标按钮提供明确的 `aria-label`。
- 加载和操作结果使用 `aria-live`，错误使用 `role="alert"`。
- 80% 缩放和窄窗口下，顶栏、工具栏和操作按钮允许换行，不能横向溢出。

## 6. 界面缩放

当前提供五档整体缩放：

- 80%
- 90%
- 100%
- 110%
- 120%

缩放通过根元素 CSS 变量 `--ui-scale` 调整基础字号，使用 `rem` 的布局和控件随之变化。当前选择值由 Python 原子写入程序旁的 `data/config.json`，不受本地资源服务随机端口影响。

应用启动从 `bootstrap()` 取得 `uiScale`；旧版配置自动迁移，缺失或非法值回退到 100% 并尝试写回规范值。前端不再读取或写入 `localStorage`，旧页面来源中的残留值不会覆盖便携配置。

用户切换档位时先立即应用，再调用 Python 串行原子保存。保存失败不回滚当前界面，只在缩放控件附近显示“缩放设置保存失败，下次启动可能恢复默认值”。

## 7. 封面输入

每个游戏只保留当前一张封面。支持：

- 通过原生文件对话框选择 PNG、JPEG、WebP 或 BMP。
- 从浏览器剪贴板读取图片并以 PNG 数据提交。
- 替换已有封面。
- 移除封面，但不影响游戏记录。

本地原图只读导入，不移动、不覆盖也不删除用户源文件。剪贴板没有图片、权限被拒绝、文件损坏或超出限制时显示错误。

## 8. 图片处理与存储

图片进入后端后执行：

1. 最多读取 50 MiB。
2. 根据实际解码格式验证，不信任扩展名或 MIME。
3. 限制单边最大 16,384 像素、总像素最大 6400 万。
4. 应用 EXIF 方向并转换为稳定颜色模式。
5. 保存规范化原图。
6. 生成 400×600 的 WebP 2:3 居中裁剪缩略图。
7. 先写 `data/temp`，再移动到最终目录并更新数据库。

文件位置：

```text
data/covers/original/
data/covers/thumbs/
```

文件名包含游戏 ID、封面修订号和随机后缀，替换封面后 URL 随修订号变化，避免 WebView 缓存旧图。新文件或数据库更新失败时清理新文件并保留旧记录；成功后再删除旧受管文件。

## 9. 封面提供边界

前端不读取 `file://` 路径。封面通过带随机会话令牌的回环只读服务获取：

- 缩略图用于网格。
- 规范化原图用于详情。
- 游戏 ID 必须在数据库中存在对应封面记录。
- 解析后的文件必须仍位于受管封面目录。
- 外部任意路径不能通过 URL 参数读取。

## 11. 验收基准

- 大量游戏以响应式 2:3 网格显示，搜索和筛选只改变可见项。
- 无封面游戏显示稳定占位图，不产生损坏图片请求。
- 本地选择和粘贴截图都能设置封面。
- 非图片、损坏图片、超大文件和超大尺寸会被拒绝。
- 替换或移除封面不会修改用户原文件。
- 详情只显示一个关闭按钮。
- 点击遮罩、按 `Esc` 或点击关闭按钮都能关闭详情。
- 抽屉打开时主界面不滚动，抽屉内部可独立滚动。
- 抽屉打开和关闭不会因主滚动条消失而横向跳动。
- 焦点不会通过 Tab 移到被遮罩的主页面。
- 详情宽度正常情况下接近窗口的 40%，同时遵守 32rem 最小值、48rem 最大值和窄窗口 92vw 上限。
- 详情使用规范化原图并完整显示，不使用网格裁剪缩略图。
- 内容顺序为概览、封面、游戏设置、存档位置、游戏引擎、游戏记录。
- 游戏设置保留完整安装路径和主程序，并默认展开；路径可直接打开。
- 存档位置默认展开，查找存档仍需用户主动触发，规则设置默认折叠。
- 游戏引擎合并自动结果与手动设置并默认折叠；游戏记录位于底部并默认折叠。
- 关闭并重新打开详情后恢复固定默认折叠状态，不记忆上次状态。
- 缩放可在 80%～120% 间选择；重启和迁移整个便携目录仍能通过配置版本 2 恢复所选比例。
- 缩放配置保存失败不撤销当前比例，并显示下次启动可能恢复默认值的警告。
- 普通模式点击卡片打开详情；批量模式点击允许处理的卡片只切换选择，`save_only` 始终不可选择。
- 全选只加入当前筛选结果，切换筛选保留原选择，并正确统计已安装和失效数量。
- 没有选择时批量删除不可用；最终确认准确说明两类记录处理语义和不删除用户文件的边界。
- 批量成功后只刷新一次游戏库并显示处理摘要；整批失败不留下前端“部分成功”状态。
- 各缩放档位和窄窗口下不出现不可操作的横向溢出。

## 12. 后续工作

- 游戏数量显著增加并出现实测性能问题后，再考虑虚拟列表或封面懒加载；首版不预先引入复杂虚拟化。
- 在真实 pywebview 窗口中人工验收详情抽屉的 80%、100%、120% 缩放，以及窄窗口、常规窗口和 1920px 宽窗口表现。
