# GameShelf 封面与游戏库界面

> 文档性质：当前有效的模块设计与验收基准；适用版本：V0.1；最后更新：2026-08-13；状态：已实现。

## 1. 模块目标

主界面以封面网格展示游戏库，并提供搜索、筛选、根目录管理和右侧游戏详情。每个游戏只设置一张封面，可从本地文件选择或直接粘贴剪贴板截图。

界面优先保持游戏库浏览上下文：打开详情时不切换整页，关闭后回到原卡片位置。

## 2. 主界面布局

主界面由以下区域组成：

- 顶栏：应用标题、界面缩放和添加游戏目录。
- 左侧栏：多个扫描根目录及扫描操作。
- 内容区：游戏数量、移动建议、搜索和筛选工具栏、封面网格。
- 详情层：选中游戏后从右侧显示的模态详情抽屉。

游戏网格使用响应式 CSS Grid。窗口或界面缩放改变时，浏览器根据可用宽度自动调整每行卡片数量；游戏数据和图片组件不会因此重新请求或重复创建整份游戏库。

## 3. 游戏卡片

每张卡片显示：

- 2:3 封面缩略图；没有封面时显示标题首字符占位图。
- 游戏标题。
- 安装状态。
- 已识别或手动设置的引擎标签。

卡片标题允许省略显示，但保留完整文本提示。点击卡片打开详情，键盘焦点进入抽屉；关闭后焦点返回原卡片。

主界面支持：

- 按标题即时搜索。
- 按 `installed`、`missing`、`save_only` 状态筛选。
- 按当前采用的引擎筛选。
- 无游戏、无搜索结果、连接失败和扫描错误等独立状态。

## 4. 详情抽屉

详情抽屉固定在窗口右侧，宽度为 `min(26.25rem, 92vw)`，拥有自己的纵向滚动区域。当前包含：

- 完整封面和游戏标题。
- 安装状态、引擎结果与检测证据。
- 手动引擎选择。
- 封面选择、粘贴、替换和移除。
- 已确认存档位置和静态建议。
- 标题、主 EXE、工作目录、参数及环境变量设置。

### 4.1 关闭方式

抽屉只保留右上角一个关闭按钮，并支持：

- 点击左侧半透明遮罩关闭。
- 按 `Esc` 关闭。
- 关闭后恢复打开详情的卡片焦点。

抽屉内普通空白区域不关闭，避免编辑表单时误操作。

### 4.2 滚动行为

- 抽屉打开时锁定主页面滚动。
- 主页面滚动条占用的宽度通过 `body` 右侧补偿，避免内容横向跳动。
- 遮罩拦截滚轮，不让左侧页面随详情滚动。
- 抽屉内部独立滚动，并使用 `overscroll-behavior` 阻止滚动链传回主页面。
- 抽屉滚动条位于抽屉内部，不与主界面滚动条并排显示。

### 4.3 网格策略

打开抽屉时，主界面网格不为抽屉重新缩窄和重排。抽屉以覆盖层形式显示，左侧加 22% 黑色半透明遮罩。

选择覆盖方案的原因：

- 用户打开详情时主要关注当前游戏，不需要同时操作网格。
- 不会因网格列数变化造成卡片大幅移动。
- 大型游戏库不发生额外布局抖动。
- 点击遮罩即可清楚返回游戏库。

## 5. 键盘与可访问性

- 抽屉使用 `role="dialog"` 和 `aria-modal="true"`。
- 打开后把焦点移入抽屉。
- `Tab` 和 `Shift+Tab` 在抽屉可聚焦元素间循环。
- `Esc` 与关闭按钮行为一致。
- 图标按钮提供明确的 `aria-label`。
- 加载和操作结果使用 `aria-live`，错误使用 `role="alert"`。
- 80% 缩放和窄窗口下，顶栏、工具栏和操作按钮允许换行，不能横向溢出。

## 6. 界面缩放

当前提供五档整体缩放：

- 80%
- 90%
- 100%
- 110%
- 120%

缩放通过根元素 CSS 变量 `--ui-scale` 调整基础字号，使用 `rem` 的布局和控件随之变化。选择值写入 `localStorage` 的 `gameshelf.ui-scale`；旧版 130% 值会迁移为 120%。由于本地资源服务当前使用随机端口，跨应用启动能否稳定恢复仍需在真实 pywebview 中验收，必要时迁入 `data/config.json`。

存储不可用或值无效时回退到 100%，但本次运行中的缩放操作仍然有效。

## 7. 封面输入

每个游戏只保留当前一张封面。支持：

- 通过原生文件对话框选择 PNG、JPEG、WebP 或 BMP。
- 从浏览器剪贴板读取图片并以 PNG 数据提交。
- 替换已有封面。
- 移除封面，但不影响游戏记录。

本地原图只读导入，不移动、不覆盖也不删除用户源文件。剪贴板没有图片、权限被拒绝、文件损坏或超出限制时显示错误。

## 8. 图片处理与存储

图片进入后端后执行：

1. 最多读取 50 MiB。
2. 根据实际解码格式验证，不信任扩展名或 MIME。
3. 限制单边最大 16,384 像素、总像素最大 6400 万。
4. 应用 EXIF 方向并转换为稳定颜色模式。
5. 保存规范化原图。
6. 生成 400×600 的 WebP 2:3 居中裁剪缩略图。
7. 先写 `data/temp`，再移动到最终目录并更新数据库。

文件位置：

```text
data/covers/original/
data/covers/thumbs/
```

文件名包含游戏 ID、封面修订号和随机后缀，替换封面后 URL 随修订号变化，避免 WebView 缓存旧图。新文件或数据库更新失败时清理新文件并保留旧记录；成功后再删除旧受管文件。

## 9. 封面提供边界

前端不读取 `file://` 路径。封面通过带随机会话令牌的回环只读服务获取：

- 缩略图用于网格。
- 规范化原图用于详情。
- 游戏 ID 必须在数据库中存在对应封面记录。
- 解析后的文件必须仍位于受管封面目录。
- 外部任意路径不能通过 URL 参数读取。

## 10. 代码职责

| 区域 | 主要职责 |
| --- | --- |
| `src/gameshelf/covers/image_pipeline.py` | 图片限制、解码、方向修正和缩略图生成 |
| `src/gameshelf/covers/service.py` | 文件与数据库补偿式更新、替换和清理 |
| `src/gameshelf/web/asset_server.py` | 只读提供 UI 与受管封面 |
| `frontend/src/features/library/GameGrid.vue` | 网格和详情选择状态 |
| `frontend/src/features/library/GameDetailDrawer.vue` | 抽屉、滚动锁定和焦点管理 |
| `frontend/src/features/covers/CoverActions.vue` | 选择、粘贴、替换和移除封面 |
| `frontend/src/features/preferences` | 界面缩放值、迁移和选择控件 |
| `frontend/src/features/library/library.css` | 网格、抽屉和详情内容样式 |

## 11. 验收基准

- 大量游戏以响应式 2:3 网格显示，搜索和筛选只改变可见项。
- 无封面游戏显示稳定占位图，不产生损坏图片请求。
- 本地选择和粘贴截图都能设置封面。
- 非图片、损坏图片、超大文件和超大尺寸会被拒绝。
- 替换或移除封面不会修改用户原文件。
- 详情只显示一个关闭按钮。
- 点击遮罩、按 `Esc` 或点击关闭按钮都能关闭详情。
- 抽屉打开时主界面不滚动，抽屉内部可独立滚动。
- 抽屉打开和关闭不会因主滚动条消失而横向跳动。
- 焦点不会通过 Tab 移到被遮罩的主页面。
- 缩放可在 80%～120% 间选择；同一存储来源内可以恢复，跨应用启动持久性需要发布前实测。
- 各缩放档位和窄窗口下不出现不可操作的横向溢出。

## 12. 后续工作

- 如果用户需要完全随目录迁移的界面偏好，把缩放值从 `localStorage` 迁入 `data/config.json`。
- 游戏数量显著增加并出现实测性能问题后，再考虑虚拟列表或封面懒加载；首版不预先引入复杂虚拟化。
- 删除/忽略游戏的操作入口应与详情抽屉和筛选状态统一设计，见模块 02。
