# GameSave Scout 批量封面向导实施计划

> 实施状态：2026-08-17 已完成。最终自动门禁为 Python 623 项、前端 104 项，并通过 Ruff、mypy、Vue 类型检查、生产构建、schema 1 启动冒烟和 Markdown 本地链接检查；任务 9 步骤 5、6 的受控真实 VNDB 冒烟与 pywebview 工作台人工验收均已由用户完成并确认通过。

> **供智能代理执行：** 必须使用 `superpowers:executing-plans` 按任务顺序实施；本项目明确不使用子代理。步骤使用复选框跟踪。

**目标：** 在不新增数据库表的前提下，实现单窗口全屏批量封面工作台，统一审核 VNDB、拖放/粘贴、游戏目录浅层扫描和自定义封面目录候选，并在用户确认后复用现有封面服务逐项保存。

**架构：** Python 以单活动会话管理队列、候选元数据和 `data/temp/cover-wizard/<session-id>` 临时内容；耗时来源通过现有 `TaskRegistry` 执行，前端 Pinia store 轮询任务和会话快照。候选预览通过现有随机令牌回环服务按会话 ID 与候选 ID 提供；未采用候选不写 SQLite，采用时调用现有 `CoverService`。

**技术栈：** Python 3.12、标准库 `urllib`、Pillow、RapidFuzz、pywebview、Vue 3、TypeScript、Pinia、Vitest、pytest。

## 全局约束

- 直接在当前本地 `main` 工作，不创建分支或 worktree，不使用子代理。
- 不自动执行 `git commit`；每个任务结束只保留未提交 diff，供用户通过 Codex 审核/撤销。
- 仓库设计与开发文档使用中文；当前设计以模块 01、模块 03 和开发路线图为准。
- 不新增 Python 或前端运行时依赖；VNDB 使用标准库 HTTPS 客户端与可注入传输协议。
- SQLite schema 保持版本 1，不新增候选表，不创建数据库迁移。
- `data/config.json` 升级为版本 3；版本 1/2 迁移必须保留合法 `uiScale`，联网默认关闭。
- 同一时间只允许一个批量封面会话、一个候选收集后台任务；当前搜索与批量搜索共享限速。
- VNDB 每游戏默认 5 个候选、可设置 1～20；浅层扫描默认 10 个、可设置 1～100。
- 游戏目录扫描深度最多 1；自定义封面目录非递归；所有外部原图只读且不跟随重解析点。
- 单张图片最多 50 MiB、单边最多 16,384 像素、总像素最多 6,400 万；继续复用现有格式白名单。
- 在线请求只发送游戏标题；只接受 `https://api.vndb.org/kana/vn` 与受控 `https://t.vndb.org/` 图片地址。
- 自动测试不得访问真实网络；真实 VNDB 仅在实现完成后由显式人工冒烟命令验证。
