## 目标

为 GameShelf 0.1.0 建立可重复、可审计的 Windows x64 便携版发布流程，产出：

- PyInstaller onedir 应用目录；
- 包含 WebView2 Fixed Version Runtime x64 的离线 ZIP；
- 与 ZIP 对应的 SHA-256 文件；
- 可被本机和干净 Windows 虚拟机验证的结构化 smoke 报告；
- 记录文件版本、来源和哈希的发布清单。

发布包必须能够在没有 Python、Node.js、Visual Studio 和系统 WebView2 Runtime 的 Windows 10/11 x64 环境中启动。发布范围不包含 onefile、安装器、自动更新、代码签名、上传或创建远端 Release。

## 已确认的架构

1. 前端继续由 Vite 构建到 resources/ui。
2. Python 桌面程序由 PyInstaller 生成 onedir，用户数据仍位于可执行文件同级 data。
3. PyInstaller 内部依赖位于应用目录的 _internal；项目资源统一从 _internal/resources 解析。
4. WebView2 Fixed Version Runtime 不由脚本联网下载。用户提供微软官方 x64 CAB 的绝对路径，仓库内受控配置记录文件名、版本、架构、来源 URL 和 SHA-256。
5. 构建脚本只在 build/release 内创建临时内容，只替换 dist 下当前版本的精确目标。
6. ZIP 根目录是 GameShelf-0.1.0-win-x64，内部包含 GameShelf.exe、_internal、WebView2 Runtime、README、LICENSE、第三方声明和发布清单，不包含 data。
7. GUI 程序无控制台。冻结环境启动失败时使用原生 Windows 对话框；结构化 smoke 模式写 JSON 并以退出码表达结果。

## 本计划新增、需要明确批准的审核项

微软文档说明：Windows 10 上，Fixed Version 120 及以上用于 unpackaged Win32 应用时，需要给运行时目录授予两个 AppContainer SID 的读取和执行权限。ZIP 不携带可依赖的 NTFS ACL，因此只在构建机上处理不能解决最终用户解压后的权限。

计划采用以下行为：

- 仅在冻结应用、Windows 10、本地磁盘上的内置 Fixed Runtime 启动前执行检查与修复；
- 调用 System32 下的 icacls.exe，shell=False，目标严格限定为当前发布目录中的 WebView2 Runtime 根目录；
- 只授予 S-1-15-2-2 和 S-1-15-2-1 的 OI、CI、RX 权限，不请求管理员权限，不修改其他目录；
- Windows 11 和源码开发模式不执行该步骤；
- 路径不是本地磁盘、权限修复失败或运行时不完整时，在创建 WebView 之前明确失败；
- JSON smoke 模式把该检查结果写入报告，不弹窗；普通冻结启动通过原生对话框显示可操作的错误。

参考：

- https://learn.microsoft.com/microsoft-edge/webview2/concepts/distribution
- https://pywebview.flowrl.com/api/

用户批准本计划，即视为批准上述受限 ACL 行为。若不接受，需要在开始实现前重新选择发布方式。

## Task 9：用户提供真实官方 CAB 后锁定受控配置

这是第二个明确停点。实现走到这里后，需要用户提供微软官方 x64 Fixed Version Runtime CAB 的绝对路径。

执行者应：

1. 计算 CAB SHA-256；
2. 从官方来源和 CAB 内容核对版本、架构、文件名；
3. 把真实值写入 release/webview2-runtime.json；
4. 让用户审核版本、来源 URL 和 SHA-256；
5. 不复制 CAB 到仓库，不自动选择更新版本，不联网下载。

配置格式：

~~~json
{
  "formatVersion": 1,
  "version": "由真实 CAB 决定",
  "architecture": "x64",
  "archiveFileName": "由真实 CAB 决定",
  "sha256": "由真实 CAB 决定",
~~~
