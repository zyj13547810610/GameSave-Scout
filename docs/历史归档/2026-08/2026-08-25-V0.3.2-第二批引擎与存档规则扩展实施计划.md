# V0.3.2 第二批引擎与存档规则扩展实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 本项目约定覆盖默认推荐：在当前 `main` 内由当前任务顺序执行，不创建 worktree、不使用子代理。

**Goal:** 增加 GARbro 逐项复核后筛出的 45 个强特征与 7 个实验性同人/Galgame 内置引擎规则，为声明式存档位置加入存在性策略，并把 Ren'Py、RPG Maker 与 NScripter 的等价代码提示迁入可见、可禁用的 YAML 规则。

**Architecture:** 引擎识别继续使用现有受限 YAML 证据操作；GARbro 只提供锁定提交的候选与格式证据。存档位置新增缺省兼容的 `require_existing`，由规则提供者携带语义、单游戏静态发现执行过滤、批量扫描继续只接受实际命中。Ren'Py 的小型受限解析器只产生安全元数据，路径声明仍由 YAML 决定。

**Tech Stack:** Python 3.12、PyYAML、pytest、mypy、Vue 3、TypeScript、Pinia、Vitest、Vite。

**Spec:** `docs/superpowers/plans/2026-08-12-GameSave-Scout-04-游戏引擎识别.md`、`docs/superpowers/plans/2026-08-12-GameSave-Scout-05-静态存档位置.md`

## 文件结构与职责

- `src/gamesave_scout/saves/rule_schema.py`：解析 `require_existing` 与 `{renpy_save_directory}`，保持旧规则缺省兼容。
- `src/gamesave_scout/rules/serialization.py`：只在 `require_existing=true` 时写出字段，保持 YAML 紧凑。
- `src/gamesave_scout/rules/management.py`：编辑草稿恢复明确布尔值；本地测试继续报告位置存在性。
- `src/gamesave_scout/saves/models.py`：在运行时候选中携带声明式位置的存在性要求。
- `src/gamesave_scout/saves/builtin_rules.py`：把规则字段传入候选，不负责访问磁盘。
- `src/gamesave_scout/saves/static_discovery.py`：完成受限探测后过滤 `require_existing` 未命中的候选。
- `src/gamesave_scout/saves/engine_hints.py`：把 Ren'Py 字符串读取改为安全元数据加载，并在对照通过后移除 RPG Maker/NScripter 旧候选分支。
- `resources/rules/builtin/engines.yaml`：模块 04 的 52 个 GARbro 直接特征内置识别规则；不加入依赖复杂解析或新证据操作的候选。
- `resources/rules/builtin/saves.yaml`：Ren'Py、RPG Maker 各世代与 NScripter 内置存档规则。
- `resources/rules/schemas/saves.schema.json`：公开 `require_existing` 和新占位符契约。
- `frontend/src/api/contracts.ts`：前端草稿的可选兼容字段。
- `frontend/src/features/rules/RuleLocationEditor.vue`：显示条件下拉框与 Ren'Py 占位符按钮。
- `frontend/src/features/rules/SaveRuleForm.vue`、`ruleManagementStore.ts`：新建和预填位置使用明确默认值。
- `tests/unit`、`tests/integration`、`frontend/tests`：schema、运行语义、正反夹具、迁移对照和界面回归。
