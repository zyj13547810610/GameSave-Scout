# GameShelf V0.2 自定义游戏分组实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. 本项目明确不使用子代理；所有步骤由当前任务按顺序执行，每个任务完成测试后提交一次。

**目标：** 在 V0.2.0 中加入扁平的用户自定义游戏分组，使同一游戏可以加入多个分组，并支持详情编辑、批量加入/移出、组合筛选和完整的错误恢复。

**架构：** 数据库使用 `game_groups` 与 `game_group_memberships` 两张规范化表保存分组及多对多关系；所有写操作经现有 `DbWriter` 串行事务执行。读取游戏列表时使用有界批量查询水合 `groupIds`，避免 N+1。pywebview 桥接层暴露稳定 DTO 和错误码，Vue store 同时管理分组清单与会话级单选筛选，三个界面入口共用同一组后端语义。

**技术栈：** Python 3.12、SQLite、pywebview、Vue 3、TypeScript、Vite、Vitest、pytest、Ruff、mypy。

## 全局约束

- 直接在当前本地分支开发，不创建分支或 worktree，不使用子代理。
- V0.2 数据库 schema 为 3，只支持新建数据库；schema 1、2 或 `user_version = 0` 但已有用户表的数据库必须拒绝启动，并明确提示用户手动移动或删除 `data/library.db`。
- 绝不自动删除、重命名、覆盖或备份旧数据库；`data/covers` 中的文件不受旧库拒绝流程影响。
- 每个游戏可以属于多个分组；分组适用于 `installed`、`missing` 和 `save_only`。
- 首版只做扁平名称分组，不做层级、颜色、图标、智能规则、卡片徽章或多分组 AND/OR 筛选。
- 分组上限 200 个；名称去除首尾空白后为 1～40 个字符，禁止控制字符；使用 NFKC 与 `casefold()` 生成唯一规范名，显示名保留用户输入的文字与大小写。
- 详情保存一次性替换该游戏的全部分组关系；批量操作一次最多接收 500 个原始游戏 ID，只支持对一个分组执行加入或移出。
- 批量 ID 去重后处理；已存在的加入和已不存在的移出计入 `unchangedCount`，任一分组或游戏不存在时整笔事务回滚。
- 分组列表按 `created_at`、`id` 稳定排序；游戏的 `groupIds` 同样按分组创建顺序、分组 ID 排序。
- 所有成功写入都刷新相关游戏与分组计数；失败时保留用户当前选择、对话框和批量上下文。
- 现有批量删除只允许 `installed` 与 `missing`；选择中含 `save_only` 时必须禁用删除并解释原因，但仍可执行分组操作。

```python
def group_ids_by_game(
    connection: sqlite3.Connection,
    game_ids: Sequence[str],
) -> dict[str, tuple[str, ...]]:
    unique_ids = tuple(dict.fromkeys(game_ids))
    if not unique_ids:
        return {}
    placeholders = ", ".join("?" for _ in unique_ids)
    rows = connection.execute(
        f"""
        SELECT membership.game_id, membership.group_id
        FROM game_group_memberships AS membership
        JOIN game_groups AS group_row ON group_row.id = membership.group_id
        WHERE membership.game_id IN ({placeholders})
        ORDER BY group_row.created_at, group_row.id
        """,
        unique_ids,
    ).fetchall()
    collected: dict[str, list[str]] = {game_id: [] for game_id in unique_ids}
    for row in rows:
        collected[row["game_id"]].append(row["group_id"])
    return {game_id: tuple(ids) for game_id, ids in collected.items()}
```

为列表查询实现 `games_from_rows(connection, rows)`，为单条查询实现 `game_from_row_with_groups(connection, row)`；列表必须先收集 ID 再调用一次 `group_ids_by_game`。

`GroupRepository.list_groups()` 使用单条 `LEFT JOIN` 聚合查询：

```sql
SELECT
    group_row.id,
    group_row.name,
    group_row.created_at,
    group_row.updated_at,
    COUNT(membership.game_id) AS game_count
FROM game_groups AS group_row

GROUP BY group_row.id
ORDER BY group_row.created_at, group_row.id
```

名称处理函数：

```python
def _validated_group_name(value: str) -> tuple[str, str]:
    display = value.strip()
    if not 1 <= len(display) <= MAX_NAME_LENGTH:
        raise InvalidGroupName
    if any(unicodedata.category(character).startswith("C") for character in display):
        raise InvalidGroupName
    normalized = unicodedata.normalize("NFKC", display).casefold()
    return display, normalized
```
