# V0.3.5 引擎分类与规则扩充 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` in the current session to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 本项目明确不使用子代理，不创建分支或额外 worktree。

**Goal:** 在不改变 SQLite schema 4、存档规则匹配和现有检测触发时机的前提下，为全部引擎规则增加两类维护生态，新增 14 个低风险引擎结果，并在用户引擎规则表单中提供明确的分类选择。

**Architecture:** `EngineRule.category` 与代码型 `EngineOption.category` 共同承载 `general` / `visual_novel_doujin` 元数据；分类只参与 YAML 往返、复制和规则编辑，不参与检测分数、验证指纹或存档匹配。六个可由现有声明式证据安全表达的引擎加入 `engines.yaml`，八个需要组合运行时布局的引擎由一个有界代码检测器处理；前端只扩展引擎规则编辑器，不扩展游戏库筛选或卡片展示。

**Tech Stack:** Python 3.12、dataclass/typing、PyYAML、pytest、Vue 3、TypeScript、Pinia、Vitest、JSON Schema、Ruff、mypy、Vite。

**Spec:** `docs/superpowers/specs/2026-08-12-GameSave-Scout-总体设计.md` 的 V0.3 与引擎识别模型，`docs/superpowers/plans/2026-08-12-GameSave-Scout-01-基础架构.md` 第 7.2 节，`docs/superpowers/plans/2026-08-12-GameSave-Scout-03-封面与游戏库界面.md` 第 3.4 节，`docs/superpowers/plans/2026-08-12-GameSave-Scout-04-游戏引擎识别.md` 第 13.7 节，以及 `docs/superpowers/plans/2026-08-12-GameSave-Scout-开发路线图.md` 第 9.6 节。

固定接口：

```python
type EngineCategory = Literal["general", "visual_novel_doujin"]

@dataclass(frozen=True)
class EngineRule:
    metadata: RuleMetadata
    label: str
    notes: str | None
    category: EngineCategory | None
    variant: str | None
    threshold: float
    required: tuple[EvidenceRule, ...]
    optional: tuple[EvidenceRule, ...]
    negative: tuple[EvidenceRule, ...]

@dataclass(frozen=True)
class EngineOption:
    id: str
    label: str
    experimental: bool = False
    category: EngineCategory | None = None
```

```ts
export type EngineCategory = 'general' | 'visual_novel_doujin'

export interface EngineRuleDraft extends RuleDraftCommon {
  type: 'engine'
  category?: EngineCategory | null
}
```
