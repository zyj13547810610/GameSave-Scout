# Ludusavi 清单更新修复实施计划

> 实施状态：已完成。内置清单换行校验、文件组保护、事务式更新、来源降级、桥接反馈和前端状态展示均已实现并验证。

> **供智能体执行：** 必须使用 `superpowers:executing-plans` 在当前会话逐项实施；每一步使用复选框跟踪。用户已明确要求不使用子代理。

**目标：** 修复 Windows 换行转换造成的 Ludusavi 内置清单初始化失败，并保证更新失败时继续使用最后一次有效清单，同时提供明确的阶段、错误与降级反馈。

**架构：** `LudusaviProvider` 独占内置、当前和备份文件组的验证与原子替换；桥接 API 只负责任务阶段和结构化结果；`StaticSaveDiscovery` 在官方清单不可用时跳过该来源；`TaskRegistry` 记录意外异常；Vue 组件展示当前清单与更新结果。所有磁盘写入均先落到 `data/temp`，清单与元数据使用同一互斥锁保护。

**技术栈：** Python 3.12、PyYAML、pytest、Vue 3、TypeScript、Vitest、ruff、mypy、Git attributes。

## 全局约束

- 只有用户主动点击“检查并更新清单”才访问网络；启动时不得自动联网。
- 下载上限保持为 64 MiB，超时保持为 30 秒。
- 原始 SHA-256 失败后只允许 `CRLF -> LF` 规范化；规范化哈希必须与内置元数据完全一致。
- 下载、校验、备份或替换失败不得修改最后一次有效清单或清除存档发现缓存。
- 当前清单不可用时，先恢复最近有效成组备份，再回退到内置清单。
- 当前、备份和内置清单都不可用时，只跳过 Ludusavi 官方规则；自定义清单和引擎规则继续工作。
- 意外异常完整堆栈只写入 `data/logs/gameshelf.log`，不得在前端响应中暴露。
- 不增加数据库迁移，不改变便携目录布局，不实施引擎识别、游戏移除或扫描进度功能。
- 遵循 TDD：每个行为先增加失败测试，再进行最小实现。

在 `ludusavi_provider.py` 增加：

```python
def _validated_manifest_bytes(
    path: Path, expected_sha256: str, *, allow_crlf_repair: bool
) -> bytes:
    content = path.read_bytes()
    if hashlib.sha256(content).hexdigest() == expected_sha256:
        return content
    if allow_crlf_repair:
        normalized = content.replace(b"\r\n", b"\n")
        if normalized != content and hashlib.sha256(normalized).hexdigest() == expected_sha256:
            return normalized
    raise SnapshotUpdateError("Ludusavi 清单的 SHA-256 与元数据不一致。")
```

让 `ensure_initial_snapshot()` 读取该函数的返回值，并用新的 `_atomic_write_bytes(content, destination)` 写入当前清单；元数据仍按原文件复制。`allow_crlf_repair=True` 只用于内置清单，当前清单和下载文件始终传 `False`。

- [x] **步骤 3：实现成组验证与恢复**

增加数据类和互斥锁：

```python
from threading import RLock


@dataclass(frozen=True, slots=True)
class SnapshotPair:
    manifest: Path
    metadata: Path
```

在构造函数中设置 `self._lock = RLock()`。让 `ensure_initial_snapshot()`、`load()`、`metadata()` 和 `update_explicitly()` 的文件组操作进入同一把锁。

备份命名使用同一个随机键：

```python
def _backup_active_pair(self) -> SnapshotPair | None:
    if not self.active_manifest.is_file() or not self.active_metadata.is_file():
        return None
    key = f"{datetime.now(UTC):%Y%m%dT%H%M%SZ}-{uuid4().hex[:8]}"
    pair = SnapshotPair(
        self.previous_dir / f"manifest-{key}.yaml",
        self.previous_dir / f"manifest-{key}.json",
    )
    shutil.copy2(self.active_manifest, pair.manifest)
    shutil.copy2(self.active_metadata, pair.metadata)
    return pair
```

`ensure_initial_snapshot()` 的顺序必须是：严格验证当前组 → 从新到旧验证并恢复备份组 → 验证/规范化内置组。恢复时通过临时文件复制完整组，失败后继续尝试更旧备份或内置清单；无效文件不得直接返回。

成组验证实现为：

```python
def _validate_pair(
    pair: SnapshotPair, *, allow_crlf_repair: bool
) -> tuple[SnapshotMetadata, bytes]:
    if not pair.manifest.is_file() or not pair.metadata.is_file():
        raise SnapshotUpdateError("Ludusavi 清单文件组不完整。")
    metadata = _read_metadata(pair.metadata)
    content = _validated_manifest_bytes(
        pair.manifest,
        metadata.sha256,
        allow_crlf_repair=allow_crlf_repair,
    )
    _validate_manifest_bytes(content)
    return metadata, content
```

`_validate_manifest_bytes(content: bytes) -> None` 使用 `content.decode("utf-8")` 和 `io.StringIO` 调用现有 `parse_manifest(..., skip_invalid_paths=True)`；UTF-8 或 YAML 错误转换为 `SnapshotUpdateError`，并保留原异常作为 `__cause__`。

恢复备份时，先对候选组执行 `_validate_pair(..., allow_crlf_repair=False)`，再调用 `_install_pair_bytes(manifest_bytes, metadata_bytes)`。该函数分别在 `temp_dir` 创建清单和元数据临时文件、写入、flush、`os.fsync`，最后才 `os.replace` 到当前路径。若第二次替换失败，它必须删除刚写入的当前清单，避免留下貌似完整但不匹配的文件组；循环随后尝试下一个备份或内置组。

`_prune_previous()` 按共同键识别 `.yaml`/`.json`，只保留最近两组，并删除孤立文件。

`update_explicitly()` 在锁内尝试取得当前元数据；`SnapshotUpdateError` 表示无当前快照时将 `current=None`，但继续进行显式网络更新，不发送 ETag。按顺序上报 `connecting`、`downloading`、`validating`、`replacing`。

`_replace_pair` 的签名和事务边界固定为：

```python
def _replace_pair(
    self,
    new_manifest: Path,
    new_metadata: Path,
    backup: SnapshotPair | None,
) -> None:
    try:
        os.replace(new_manifest, self.active_manifest)
        os.replace(new_metadata, self.active_metadata)
        self._validate_pair(
            SnapshotPair(self.active_manifest, self.active_metadata),
            allow_crlf_repair=False,
        )
    except (OSError, SnapshotUpdateError):
        self.active_manifest.unlink(missing_ok=True)
        self.active_metadata.unlink(missing_ok=True)
        if backup is not None:
            metadata, content = self._validate_pair(
                backup, allow_crlf_repair=False
            )
            self._install_pair_bytes(content, backup.metadata.read_bytes())
        raise
```

调用者在进入 `_replace_pair` 前已把新元数据写入 `temp_dir` 并 `fsync`。恢复后再次读取 `self.metadata()`，确认返回值与更新开始时的 `current` 相同；恢复本身失败时以“替换和恢复都失败”为错误消息，同时保留备份文件，供下次初始化恢复。

让 `UpdateResult.message` 在失败且 `current is not None` 时追加“当前有效清单仍可使用。”；无当前清单时追加“当前没有可用的 Ludusavi 官方清单。”。
