# V0.3.0 引擎与存档规则扩展 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不改变 SQLite schema 4、不后台扫描用户存档目录、不启动 Ludusavi 程序的前提下，建立引擎与存档“双规则库 + 共享基础层”，校准 7 个现有实验引擎、新增 LiveMaker、CMVS/CVNS、Godot，并让单游戏静态查找和批量存档扫描复用同一套安全、可诊断的内置存档规则。

**Architecture:** 引擎识别继续由专用检测器与 `resources/rules/engines.yaml` 组成；新增共享规则元数据层和独立 `resources/rules/saves.yaml`，但不把两种用途强行合并为一种 YAML。单游戏静态查找按“用户自定义清单 → 内置游戏专属规则 → Ludusavi SQLite 索引 → 内置引擎通用规则”合并候选，并区分实际存在与仅可推导路径；批量扫描只接收同一候选接口中实际存在的位置。已有 `save_locations.source` 约束保持不变，规则出处通过证据元数据表达。

**Tech Stack:** Python 3.12、dataclass/typing、PyYAML、SQLite 只读索引、pytest、Vue 3、TypeScript、Vitest、pywebview、Windows Known Folders/Registry。

**Spec:** `docs/superpowers/specs/2026-08-12-GameShelf-总体设计.md` 第 19.3 节、`docs/superpowers/plans/2026-08-12-GameShelf-04-游戏引擎识别.md` 第 6.1/13 节、`docs/superpowers/plans/2026-08-12-GameShelf-05-静态存档位置.md` 第 8.8/11.1 节、`docs/superpowers/plans/2026-08-12-GameShelf-06-动态与孤立存档发现.md` 第 14.11 节、`docs/superpowers/plans/2026-08-12-GameShelf-开发路线图.md` 第 9.1 节。

## Global Constraints

- 直接在当前本地 `main` 工作，不新建分支或 worktree；按项目约定不使用子代理，实施时使用 `superpowers:executing-plans` 在当前会话逐任务执行。
- 测试先行：每个任务先增加会失败的聚焦测试，确认失败原因属于缺失行为，再写最小实现并运行聚焦回归。
- 本轮不实现自定义规则编辑器，不加载 `data/rules/engines`，也不增加在线规则更新；编辑器留到后续 V0.3.x 单独设计和实施。
- 不增加数据库迁移，不修改 schema 4。`save_locations.source` 继续只使用 `manual/dynamic/ludusavi/engine/legacy_scan`；内置游戏规则接受后使用兼容来源 `engine`，其 `builtin` 身份保留在建议证据和批量观察中。
- 规则只能读取受限相对路径、白名单路径令牌、受限文本/二进制头和 PE 元数据；不得执行 EXE、Python、Shell、脚本、清单 SQL或归档解包。
- 规则文件、合成夹具和测试不得包含商业游戏资源、用户绝对路径、存档内容、密钥、凭据或在线响应缓存。
- `D:\library.db` 只用于最后的可选只读人工复核；生产代码和自动测试不得依赖该路径，不复制、不迁移、不提交该文件。
- `resources/manifests/ludusavi/manifest.yaml` 及其摘要/SQLite 索引不因本任务手工修改；有效索引仍只执行 SQLite 查询，只有用户点击“查找存档”且索引异常时才按现有流程内部重建。
- 保留 `resources/rules/engines.yaml` 的单行规则风格，减少后续来源审查和 Git diff 噪声。
- 每个任务完成聚焦验证后提交一次；最终完整门禁通过前不推送。提交说明使用中文或现有简洁约定，禁止把本地数据库或诊断输出加入提交。

## 计划自检结论

- 规格覆盖：共享基础层、7 条旧规则、3 个新引擎、独立存档规则库、Godot 与通用存档提示、按需查询、存在/预测分组、批量复用、诊断、版本和文档均有对应任务。
- 范围隔离：自定义规则编辑器、数据库迁移、在线规则更新、GARbro 解包、V0.3.0 便携包构建和 GitHub Release 均不在本计划内。
- 类型一致性：持久 `SaveLocationSource` 不增加 `builtin`；建议证据和批量 JSON 来源可以增加 `builtin`；`Game.engine_id` 继续保存无命名空间的兼容 ID。
- 隐私边界：真实数据库与游戏目录只用于只读人工复核，自动测试全部使用公开依据和最小合成夹具。
- 占位检查：每个任务均列出文件、失败预期、实现边界、验证命令和提交命令；实施完成时必须把所有复选框和实测记录更新为真实状态。
