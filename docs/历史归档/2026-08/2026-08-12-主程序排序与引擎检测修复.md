# GameShelf 主程序识别与引擎检测联动修复计划

> **供智能体执行者使用：** 必须使用 `superpowers:executing-plans`，按任务逐项实施本计划。用户已明确要求在主会话内执行，不使用子代理。各步骤使用复选框（`- [ ]`）跟踪进度。

**目标：** 修复复杂、汉化、嵌套和带模组游戏目录中的主程序误选，并让引擎检测使用正确的可执行文件及运行时目录；同时修复 Summer Pockets REFLECTION BLUE 的 SiglusEngine 漏判。

**架构：** 保留“扫描候选目录 → 排序 EXE → 检测引擎 → 核对数据库”的现有流程。明确的辅助 EXE 通过发现器与排序器共享的名称分类规则直接排除，风险目录仅降权；引擎检测使用有效的手动选择优先，Unity 等结构型检测器以所选 EXE 所在的安全运行时根目录识别嵌套游戏。

**技术栈：** Python 3.12、SQLite、pefile、PyYAML、pytest、ruff、mypy。

## 全局约束

- 不执行、注入、解密或改写任何游戏文件，只读取路径、文件大小、有限 PE 元数据和既有引擎特征。
- 不把用户本地商业游戏文件提交到 Git；回归测试全部使用合成目录和伪造/替换的 PE 元数据。
- `main_exe_relpath` 的手动值在重新扫描后必须保留；自动建议继续更新到 `detected_main_exe_relpath`。
- 手动主程序存在且仍是游戏目录内的 `.exe` 时，引擎检测优先使用它；无效时安全回退到自动建议并保留手动配置，不能越过游戏目录。
- `exe_arch` 必须描述当前采用的主程序：手动选择时读取手动 EXE，自动选择时读取自动第一名；重新扫描和确认移动都不能用自动建议覆盖有效手动主程序的架构。
- 主程序排序必须稳定：相同输入在不同扫描中得到相同顺序。
- 不删除任何游戏库记录。MTool、MisakaTranslator 等未列入明确辅助名称的工具目录仍保持现状；“通用地区分工具和游戏”不在本计划范围内。
- 明确辅助 EXE 的名称规则必须同时作用于递归目录发现与主程序排序；风险目录惩罚只作用于主程序排序。
- 主程序排序器直接跳过路径分段恰好为 `Mods` 的目录；手动选择 `Mods` 内的 EXE 仍然允许。目录发现器不硬编码跳过 `Mods`，需要时同时使用扫描根排除规则 `Mods` 与 `**/Mods`，分别覆盖根下直接目录和更深层目录。
- 遵循 TDD；先添加失败回归测试，再进行最小实现。

## 已确认的现象与根因

当前 `executable_ranker.py` 会递归收集候选目录下的 EXE，并主要按以下证据加分：根目录、文件名和目录名相似、PE 产品名/文件描述、文件大小。误判的核心不是随机排序，而是以下规则组合造成的系统性偏差：

1. `product_name == executable_name` 和 `file_description == executable_name` 最多贡献 50 分，但它只能说明 EXE 元数据完整，不能说明它是游戏入口。
2. 搜索所有子目录，却没有对子目录深度和 `Mods/Source/bin/Debug/obj` 等工具路径进行惩罚。
3. 大型辅助程序会因文件大小胜过没有 PE 元数据的真正游戏程序。
4. 共享名称分类只覆盖已有前缀和 `config.exe`，尚未覆盖 `UnityCrashHandler`、`UnrealCEFSubProcess`、`delfile` 和模组工具等明确的辅助角色。
5. 扫描在数据库核对前先用自动第一名检测引擎，因此用户已经手动修正主程序也无法帮助下一次引擎检测。
6. Unity 检测器只检查候选游戏目录根部；当 Unity 本体位于下一层目录时，即使选对 EXE 也会漏判。

只读诊断得到的典型结果：

| 游戏 | 当前自动第一名 | 当前分数 | 正确/期望入口 | 失败原因 |
|---|---|---:|---|---|
| Legend of Mortal | `.../UnityCrashHandler32.exe` | 6 | `.../Mortal.exe` | 崩溃处理器较大；Unity 结构位于下一层 |
| RimWorld | `Mods/.../Debug/TextExtractor.exe` | 50 | `RimWorldWin64.exe` | 模组工具的产品名和描述各自与文件名一致 |
| Operation Lovecraft | `game/Engine/.../UnrealCEFSubProcess.exe` | 21 | `game/FallenDoll.exe` | Unreal 内部 CEF 子进程获得描述和大小分 |
| ヘンタイ・プリズン | `delfile.exe` | 80 | `HENPRI.exe` | 删除辅助程序的产品名和描述完整 |
| Summer Pockets | `SiglusEngine.exe` | 42 | 用户选定的汉化启动器 | 标题前缀未被利用，文件大小决定顺序 |

Summer Pockets 的引擎漏判是独立但相关的问题：`SiglusEngine.exe` 的 PE 产品名确实为 `Siglus`，但现有规则强制要求 `Scene.pck`；本地汉化版只有 `Scene.chs` 和 `Scene.gbk`。

- [x] **步骤 1：删除 PE 元数据与自身文件名一致的高额加分**

`product_name == executable_name` 和 `file_description == executable_name` 不再加分。只有 PE 产品名/描述与游戏目录名具有明确相似度时才分别加 35/15 分。使用仍可进入候选的 `ModAssetCompiler.exe` 证明自洽元数据不会得到这 50 分；`TextExtractor.exe` 已由共享名称分类直接排除，不承担这个评分测试。

- [x] **步骤 2：加入标题包含关系**

在精确匹配和 `SequenceMatcher >= 0.8` 之外增加稳定的规范化包含关系：短侧长度至少为 6，并且 `executable_name in directory_name` 或反向包含时加 30 分，证据为 `filename_matches_title_segment`。这样 `SummerPockets` 可匹配 `Summer Pockets REFLECTION BLUE`，但 `game.exe`、`app.exe` 之类过短名称不会误触发。

- [x] **步骤 3：加入路径深度及高风险工具目录惩罚**

相对游戏目录每深入一级扣 8 分，最多扣 32 分，证据为 `nested_executable`。把 `mods` 加入现有目录硬跳过集合，使 `mods/redist/_commonredist/runtime/tools/support` 子树不进入排序；其余候选路径任一部分属于以下集合时额外扣 60 分，证据为 `auxiliary_directory`：

```python
{"source", "debug", "obj", "_redist"}
```

目录名比较不区分大小写，但必须整段等于 `mods`，不能用包含匹配。该硬跳过只属于 `rank_executables` 的递归枚举，不改变 `enumerate_candidates`，也不限制 `LibraryService.set_game_executable` 的手动选择。不要全局排除 `Binaries`，因为 Unreal 的 `*-Win64-Shipping.exe` 可能是唯一可启动入口；也不要全局排除所有 `bin`，只在它与 `Source/Debug/obj` 等工具结构同时出现时视为辅助路径。

- [x] **步骤 4：扩展共享的明确辅助程序名称排除**

normalized = _normalize(Path(name).stem)
if normalized.startswith(("unitycrashhandler", "crashpadhandler")):
    return False
if normalized in {
    "unrealcefsubprocess",
    "delfile",
    "chromedriver",
    "textractor",
    "textractorcli",

    return False
if normalized.startswith("easyanticheat") and normalized.endswith("setup"):
