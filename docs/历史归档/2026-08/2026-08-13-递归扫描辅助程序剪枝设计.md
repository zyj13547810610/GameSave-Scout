# GameSave Scout 递归扫描辅助程序剪枝设计

日期：2026-08-13
状态：已批准

## 1. 目标

递归扫描从用户指定的根目录逐层查找游戏目录。某一目录出现游戏主程序时，将该目录作为游戏候选并停止向下扫描；如果目录内只有安装器、卸载器、更新器、崩溃报告器或配置工具，则该目录不应阻断扫描，应继续寻找更深层的真实游戏目录。

## 2. 已确认行为

- “直接子目录”模式保持现状：根目录的每个可访问直接子目录都作为候选，不要求存在 EXE。
- “递归扫描”模式只检查当前目录第一层的文件，不打开或执行任何 EXE。
- 当前目录存在至少一个非辅助 EXE 时，将当前目录作为候选，并停止遍历其子目录。
- 当前目录没有 EXE，或只有辅助 EXE 时，继续遍历子目录，直到配置的最大深度。
- 当前目录同时存在辅助 EXE 和非辅助 EXE 时，仍将当前目录作为候选并停止向下扫描。
- 排除规则、符号链接与 Windows 重解析点保护、确定性排序和取消检查保持不变。

## 3. 辅助 EXE 分类

扫描发现器与主程序排序器共享同一个按文件名分类的纯函数，避免两套规则漂移。以下名称不作为游戏主程序：

- 文件名主体以 `unins`、`uninstall`、`setup`、`install`、`update`、`updater`、`crash` 或 `report` 开头；
- 文件名主体恰好为 `config`；
- 扩展名不是 `.exe`。

比较不区分大小写。第一版只复用项目已有的明确规则，不新增基于文件大小、PE 元数据或引擎特征的目录剪枝判断。

## 4. 组件边界

`gamesave_scout.scanning.executable_ranker.is_potential_game_executable_name(name)` 负责统一的文件名分类。`discovery` 负责文件系统安全检查与递归控制；`executable_ranker` 负责枚举候选主程序并评分。两者只共享分类结果，不互相调用完整扫描或评分流程。

## 5. 验收标准

- 中间目录只有 `setup.exe`、`config.exe` 等辅助程序时，递归扫描能发现更深层的 `Game.exe` 所在目录。
- 同一目录同时有 `setup.exe` 和 `Game.exe` 时，只产出该目录，不再产出其后代目录。
- 主程序排序器不再把 `config.exe` 返回为可选择的游戏主程序。
- 原有递归深度、排除、排序、取消和直接子目录模式测试继续通过。

## 6. 本次不包含

- 自动判断任意未知 EXE 是否一定为游戏；
- 修改用户手动选择主程序的能力；
- 修改引擎检测规则；
- 超出最大扫描深度继续搜索；
- 运行 EXE 或读取其运行时行为。
