# Ludusavi 静态存档性能索引实施计划

> **供智能体执行者使用：** 必须使用 `superpowers:executing-plans` 在当前任务逐项实施，并在每个任务后设置审核检查点。步骤使用复选框（`- [ ]`）跟踪；本项目约定不使用子代理。

**目标：** 为大型 Ludusavi 官方清单增加与源摘要绑定的派生 SQLite 索引，使正常有效索引的冷加载首次查找不超过 2 秒、同一运行周期后续查找不超过 1 秒，同时保持显式触发、快照恢复和其他建议来源的现有边界。

**架构：** `manifest.yaml` 与 `manifest-meta.json` 继续作为可信来源；验证阶段将 Windows 相关子集写入 `manifest-index.sqlite`。正常官方匹配只加载预规范化名称目录，并按命中的游戏 ID 读取少量规则；精确命中存在时不执行模糊匹配。索引异常只在用户点击“查找存档”后受锁重建，手动更新则在替换活动文件组前完成 YAML 验证与临时索引构建。

**技术栈：** Python 3.12、标准库 `sqlite3`、PyYAML 6、RapidFuzz 3、pytest、ruff、mypy、Vue 3、TypeScript、Vitest、Vite。

## 全局约束

- 直接使用当前本地分支，不创建分支或 worktree。
- 不使用子代理；全部工作在当前任务内完成。
- 不自动执行 `git commit`。每个任务完成后保留未提交差异，只有用户明确要求“提交”时才提交。
- 保留 README 标题下现有的 Codex 审核按钮测试注释，不修改、不撤销、不提交该测试行。
- 仓库内设计、计划、注释和用户可见文案使用中文。
- 不增加第三方运行时依赖；索引只使用 Python 标准库 `sqlite3`。
- `manifest.yaml` 与 `manifest-meta.json` 始终是可信来源；SQLite 索引只能派生、校验、重建，不能反向覆盖 YAML。
- 打开详情、展开存档区域和 Ludusavi 状态查询不得解析大型官方 YAML，也不得自动重建索引。
- 只有用户点击“查找存档”才允许查询官方索引，或在索引不可用时按需重建。
- 精确命中使用安装目录、检测标题、显示标题和主程序名；存在任一精确候选时不执行模糊匹配，完全没有精确候选时才使用 `0.86` 阈值。
- 不修改 `suggest_save_locations` 和 `ludusavi_status` 的公开 JSON 结构；官方来源失败时继续返回自定义清单和引擎提示，详细原因由日志和 Ludusavi 设置状态承载。
- 手动更新允许在后台完整解析 YAML 和构建索引；新文件组全部验证成功前不得替换旧文件组。
- 正常有效索引的性能目标为：冷加载首次查找不超过 2 秒，同一运行周期后续查找不超过 1 秒。迁移或损坏后的单次重建耗时单独记录。
- 自动测试使用“不调用 YAML 解析器”等结构性断言；真实墙钟阈值只在独立性能诊断中验收。

```python
FIXTURE_YAML = """
Alice Story:
  files:
    <base>/save: {tags: [save]}
  installDir:
    AliceGame: {}
Bob:
  alias: Alice Story
"""


def _build_fixture_index(directory: Path, manifest_sha256: str) -> Path:
    directory.mkdir(parents=True, exist_ok=True)
    path = directory / "manifest-index.sqlite"
    build_ludusavi_index(
        path,
        parse_manifest(StringIO(FIXTURE_YAML)),
        manifest_sha256=manifest_sha256,
    )
    return path


def _dump_rows(path: Path) -> tuple[tuple[object, ...], ...]:
    queries = (
        ("index_metadata", "SELECT key, value FROM index_metadata ORDER BY key"),
        ("games", "SELECT id, canonical_name FROM games ORDER BY id"),
        (
            "names",
            "SELECT game_id, candidate_order, source, display_name, normalized_name "
            "FROM names ORDER BY game_id, candidate_order",
        ),
        (
            "locations",
            "SELECT game_id, location_order, kind, path, tags_json, conditions_json "
            "FROM locations ORDER BY game_id, location_order",
        ),
    )
    with sqlite3.connect(path) as connection:
        return tuple(
            (table, *row)
            for table, query in queries
            for row in connection.execute(query)
        )
```

```sql
CREATE TABLE index_metadata (
    key TEXT PRIMARY KEY,
    value TEXT NOT NULL
);
CREATE TABLE games (
    id INTEGER PRIMARY KEY,
    canonical_name TEXT NOT NULL UNIQUE
);
CREATE TABLE names (
    game_id INTEGER NOT NULL REFERENCES games(id),
    candidate_order INTEGER NOT NULL,
    source TEXT NOT NULL CHECK (source IN ('canonical', 'install_dir', 'alias')),
    display_name TEXT NOT NULL,
    normalized_name TEXT NOT NULL,
    PRIMARY KEY (game_id, candidate_order)
);
CREATE INDEX names_normalized_name_idx ON names(normalized_name);
CREATE TABLE locations (
    game_id INTEGER NOT NULL REFERENCES games(id),
    location_order INTEGER NOT NULL,
    kind TEXT NOT NULL CHECK (kind IN ('file', 'registry')),
    path TEXT NOT NULL,
    tags_json TEXT NOT NULL,
    conditions_json TEXT NOT NULL,
    PRIMARY KEY (game_id, location_order)
);
CREATE INDEX locations_game_id_idx ON locations(game_id);
```

`index_metadata` 写入 `schema_version=1`、`manifest_sha256`、`game_count` 和 `name_count`。只给 `alias is None` 的规范游戏分配稳定递增 ID；别名沿最多 8 跳链展开到规范游戏，再按原清单顺序附加到该游戏名称列表。

- [x] **步骤 7：实现只读校验与短连接读取**

`LudusaviIndex.open()` 必须：

1. 使用 `Path.resolve().as_uri() + "?mode=ro"` 打开 SQLite。
2. 执行 `PRAGMA query_only = ON` 和 `PRAGMA trusted_schema = OFF`。
3. 要求 `PRAGMA quick_check` 唯一结果为 `ok`。
4. 检查四张表及关键列、`schema_version == 1`、64 位小写十六进制源摘要，并与 `manifest_sha256` 参数完全一致。
5. 关闭验证连接，只在 `load_names()` 和 `load_games()` 中短暂重开只读连接。
6. 将 JSON 标签与条件严格还原为 `ManifestLocationRule` 和 `ManifestCondition`；类型不符时抛出 `InvalidLudusaviIndex`。

关键查询必须按稳定顺序返回：

```sql
SELECT game_id, display_name, normalized_name, source, candidate_order
FROM names
ORDER BY game_id, candidate_order;
```

```sql
SELECT game_id, location_order, kind, path, tags_json, conditions_json
FROM locations
WHERE game_id IN (...)
ORDER BY game_id, location_order;
```

- [x] **步骤 4：实现源快照快速校验和按需索引加载**

在提供者中增加 `self.active_index = active_dir / "manifest-index.sqlite"`。`metadata()` 流程固定为：

1. 先调用 `_active_metadata_if_integrity_valid()` 以流式 SHA-256 校验 YAML 与元数据。
2. 只有源文件组缺失或摘要损坏时才调用 `ensure_initial_snapshot()`，然后重新读取活动元数据。
3. 调用 `LudusaviIndex.open(self.active_index, manifest_sha256=metadata.sha256)` 快速校验索引。
4. 索引错误转换为 `SnapshotUpdateError`，不调用 YAML 解析器或构建器，也不因为索引错误回退到较旧 YAML。

同步改造 `ensure_initial_snapshot()`：完整的三件套备份或内置资源通过 YAML 摘要、索引摘要和 SQLite 完整性快速验证后即可恢复，不解析 YAML。只有没有索引的旧两件套备份需要在恢复前完整解析一次 YAML；该行为属于兼容恢复路径。首次安装直接复制已经验证的内置三件套，使首次状态查询保持快速。

`index_session()` 在现有 `RLock` 内覆盖索引准备、名称匹配和规则读取的完整期间，避免更新在“名称已缓存、规则尚未读取”之间替换 SQLite：

```python
from collections.abc import Iterator
from contextlib import contextmanager


@contextmanager
def index_session(self) -> Iterator[LudusaviIndex]:
    with self._lock:
        metadata = self._validated_or_recovered_source_metadata()
        try:
            index = LudusaviIndex.open(
                self.active_index,
                manifest_sha256=metadata.sha256,
            )
        except (InvalidLudusaviIndex, OSError):
            index = self._rebuild_active_index(metadata)
        yield index
```

`_rebuild_active_index()` 只解析已通过摘要校验的活动 YAML，构建到 `data/temp` 唯一临时文件，重新打开验证后使用 `os.replace()` 替换活动索引。失败时删除临时文件并抛出 `SnapshotUpdateError`。

```python
def _write_snapshot_with_index(tmp_path: Path) -> Path:
    directory = tmp_path / "ludusavi"
    directory.mkdir()
    content = b"""Clair Obscur: Expedition 33:
  files:
    <winLocalAppData>/Sandfall/Saved/SaveGames/*.sav: {tags: [save]}
  installDir:
    Expedition 33: {}
Alice Story:
  files:
    <base>/save: {tags: [save]}
"""
    digest = hashlib.sha256(content).hexdigest()
    (directory / "manifest.yaml").write_bytes(content)
    (directory / "manifest-meta.json").write_text(
        json.dumps({
            "etag": None,
            "sha256": digest,
            "downloadedAt": "2026-08-14T00:00:00+00:00",
            "sourceUrl": "https://example.test/manifest.yaml",
            "upstreamCommit": None,
        }),
        encoding="utf-8",
    )
    build_ludusavi_index(
        directory / "manifest-index.sqlite",
        parse_manifest(StringIO(content.decode("utf-8"))),
        manifest_sha256=digest,
    )
    return directory
```
