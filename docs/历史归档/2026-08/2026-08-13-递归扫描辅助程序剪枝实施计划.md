# 递归扫描辅助程序剪枝实施计划

> **供智能体执行：** 必须使用 `superpowers:executing-plans` 在当前会话逐项实施；每一步使用复选框跟踪。用户已明确要求不使用子代理。

**目标：** 让递归扫描遇到纯辅助 EXE 目录时继续向下，同时让目录发现与主程序排序复用同一分类规则。

**架构：** 在 `executable_ranker` 暴露无文件系统副作用的文件名分类函数，由目录发现器在完成普通文件与链接安全检查后调用。排序器也调用该函数，从而让“能阻断递归的 EXE”和“能进入主程序候选的 EXE”保持一致。

**技术栈：** Python 3.12、pytest、ruff、mypy。

## 全局约束

- 直接子目录模式行为不变。
- 仅依据当前层文件名判断是否剪枝，不读取或执行 EXE。
- `config.exe` 与既有拒绝前缀都视为辅助程序。
- 最大深度、排除、链接保护、稳定排序和任务取消语义不变。

```python
def is_potential_game_executable_name(name: str) -> bool:
    path = Path(name)
    if path.suffix.casefold() != ".exe":
        return False
    stem = path.stem.casefold()
    return stem != "config" and not stem.startswith(_REJECTED_PREFIXES)
```

在 `_find_executables` 中使用该函数替代重复的扩展名与前缀判断，并删除 `_rank` 中已经不可达的 `config.exe` 降权分支。
