# V0.3.6 启动与封面增强 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` in the current session to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 本项目明确不使用子代理，不创建分支或额外 worktree。

**Goal:** 保持自动扫描主程序的现有启动兼容性，同时让手动选择的深层 EXE 默认从自身目录启动；为以后新采用的全部封面提供可关闭的 1920 像素自动优化；在批量封面中直接启动当前游戏，并把游戏目录图片扫描扩展为可持久化的 1～3 层。

**Architecture:** 启动工作目录继续只在执行时派生，不迁移数据库：明确人工目录优先，其次是手动主程序父目录，最后是游戏安装目录。封面保存策略和浅层扫描层数进入 `AppConfig` 版本 6，并通过现有 `coverWizardSettings` DTO 同时驱动详情与批量封面；所有正式封面采用入口仍汇聚到 `CoverService`，由它在每次导入时读取当前策略并调用同一图片管线。浅层枚举改成有界、稳定排序的逐层遍历；批量启动继续复用现有 `launch_game`，不建立第二套启动实现。

**Tech Stack:** Python 3.12、SQLite schema 4、Pillow、dataclass/typing、pytest、Vue 3、TypeScript、Pinia、Vitest、pywebview、Ruff、mypy、Vite。

**Spec:** `docs/superpowers/specs/2026-08-12-GameSave-Scout-总体设计.md` 的 V0.3.6 范围，`docs/superpowers/plans/2026-08-12-GameSave-Scout-02-游戏库扫描与启动.md` 的启动配置优先级，以及 `docs/superpowers/plans/2026-08-12-GameSave-Scout-03-封面与游戏库界面.md` 第 7～12 节。
