# V0.3.6 窗口尺寸持久化实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 GameSave Scout 在用户正常关闭后保存最后的普通窗口尺寸，并在下次启动时安全恢复。

**Architecture:** 将可持久化的宽高直接并入未发布 V0.3.6 的配置版本 6，由 `ConfigService` 继续使用串行原子写入。桌面入口在创建 pywebview 窗口前按主显示器工作区限制保存尺寸；正常关闭时优先读取 WinForms `RestoreBounds`，最大化也只保存恢复后尺寸。不持久化坐标或窗口状态，不增加前端桥接。

**Tech Stack:** Python 3.12、pywebview 6.2.1 / WinForms、JSON 原子配置、pytest、PyInstaller onedir。

**Spec:** `docs/superpowers/plans/2026-08-12-GameSave-Scout-01-基础架构.md`

## Global Constraints

- 直接在当前本地 `main` 工作，不创建分支或子代理。
- 保留用户已有的 README 修改，只在其当前内容上叠加本功能说明。
- 产品版本保持 `0.3.6`，SQLite schema 保持 4，配置版本保持 6，不新增数据库迁移。
- 默认窗口保持 `1180 × 760`，最小窗口保持 `960 × 640`。
- 只保存普通还原尺寸；不保存坐标、最大化、最小化或全屏状态。
- 只有通过引导式会话关闭检查的真实退出才保存；保存失败不得阻止退出。
- 用 `apply_patch` 编辑文件，先验证测试因功能缺失而失败，再写最小实现。

      screens = [SimpleNamespace(frame=SimpleNamespace(Width=1536, Height=824))]

  Expected: FAIL，原因是尺寸辅助模块、启动恢复和关闭保存尚未实现。

- [x] **Step 4: 实现窗口尺寸辅助边界**

  `window_size.py` 使用不可变 `WindowSize` 值对象。屏幕尺寸优先读取主屏 `frame.Width/Height`，无 frame 时读 `screen.width/height`，结构不可用时保留配置尺寸。还原尺寸优先用 `RestoreBounds / _scale`，其次读 `window.width/height`，返回前按配置同步的安全边界限制。

- [x] **Step 5: 实现启动和关闭编排**

  `_run_desktop` 在 `create_window` 前读取 `application.config.current`，使用 `module.screens` 主屏工作区限制后传入宽高。把现有 closing handler 替换为：

  ```python
  def _handle_window_closing(application: Application, window: object) -> bool:
      if not _allow_window_close(application):
          return False
      try:
          size = read_restored_window_size(window)
          application.config.set_window_size(size.width, size.height)
      except Exception:
          application.logger.warning("Unable to persist the desktop window size.", exc_info=True)
      return True
  ```

  关闭保存是最后退出的最佳努力操作，广义异常只在该边界内被吸收，不影响其他配置入口保持严格失败。
