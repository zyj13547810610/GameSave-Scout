# 损坏引擎规则降级修复实施计划

> **供智能体执行：** 必须使用 `superpowers:executing-plans` 按任务执行；每个步骤使用复选框跟踪，并严格遵守测试先行。

**目标：** 当现有 `engines.yaml` 内容无法解析或结构校验失败时，仅禁用声明式引擎检测器、记录 WARNING 并继续启动；资源缺失仍严格失败。

**架构：** `EngineDetectionService` 新增只组合内置检测器的构造入口，并把规则到检测器/选项的组合收敛到单一私有方法。应用组合根在数据库和后台写线程启动前加载规则，只对现有普通文件的非 I/O `RuleSchemaError` 执行降级；严格加载器和命令行诊断语义不变。

**技术栈：** Python 3.12、pytest、PyYAML、标准库 logging、Ruff、mypy。

## 全局约束

- 仓库设计和开发文档使用中文。
- 固定设计继续维护 `docs/superpowers/plans`；本文件是一次性实施计划，归档于 `docs/历史归档/2026-08`。
- V0.1 不新增前端横幅或原生弹窗；降级诊断只写程序旁 `data/logs/gamesave-scout.log`。
- `engines.yaml` 缺失、不再是普通文件或发生 I/O 错误时不得降级。
- `EngineDetectionService.from_rules_file(Path)` 保持严格失败，确保命令行诊断工具语义不变。
- 完整发布负载绝对路径达到或超过 260 字符明确不属于 V0.1 支持范围；本修复不修改路径处理。

- [x] **步骤 3：为引擎服务增加单一组合入口和内置模式**

在 `src/gamesave_scout/engines/service.py` 从 `rule_schema` 导入 `EngineRule`，并将现有构造逻辑改为：

```python
    @classmethod
    def builtins_only(cls) -> EngineDetectionService:
        return cls._from_rules(())

    @classmethod
    def from_rules_file(cls, rules_file: Path) -> EngineDetectionService:
        return cls._from_rules(load_engine_rules(rules_file))

    @classmethod
    def _from_rules(
        cls,
        rules: tuple[EngineRule, ...],
    ) -> EngineDetectionService:
        detectors: tuple[EngineDetector, ...] = (
            RpgMakerDetector(),
            RenPyDetector(),
            UnityDetector(),
            UnrealDetector(),
            WolfRpgDetector(),
            CreatorEngineDetector(),
            *(RuleDetector(rule) for rule in rules),
        )
        options_by_id = {option.id: option for option in _BUILTIN_OPTIONS}
        for rule in rules:
            options_by_id[rule.engine_id] = EngineOption(
                rule.engine_id, rule.label, rule.experimental
            )
        options = tuple(
            sorted(
                options_by_id.values(),
                key=lambda option: (option.experimental, option.label.casefold()),
            )
        )
        return cls(DetectorRegistry(detectors), options)
```

- [x] **步骤 4：在应用组合根实现精确降级并前移规则加载**

在 `src/gamesave_scout/bootstrap/application.py` 导入 `RuleSchemaError`，新增：

```python
def _load_engine_detection(
    rules_file: Path,
    logger: logging.Logger,
) -> EngineDetectionService:
    try:
        return EngineDetectionService.from_rules_file(rules_file)
    except RuleSchemaError as error:
        if not rules_file.is_file() or isinstance(error.__cause__, OSError):
            raise
        logger.warning(
            "声明式引擎规则加载失败，已仅启用内置检测器（%s）：%s",
            rules_file,
            error,
        )
        return EngineDetectionService.builtins_only()
```

在 `build_application()` 中，于 `configure_logging()` 和 `ConfigService` 创建之后、数据库迁移与 `DbWriter.start()` 之前调用：

```python
    engine_detection = _load_engine_detection(
        resource_paths.engine_rules_file,
        logger,
    )
```

删除原来位于 `LibraryService` 创建之后的严格加载调用。这样规则缺失仍抛错，并且不会先创建数据库或启动写线程。
